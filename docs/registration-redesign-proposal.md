# 등록·서버·탈퇴 재설계 제안 (보류 1번)

작성: 2026-11-27 · 상태: **제안 단계(승인 전에는 아무것도 바꾸지 않음)**
대상: `/등록`, `/서버등록`, `/설치`, `/서버탈퇴`, 웹 "계정 만들기", 회원 탈퇴

## 1. 지금은 이렇게 동작합니다

| 흐름 | 누가 | 하는 일 | 코드 |
|---|---|---|---|
| `/등록` | 서버 안의 누구나 | 모달에 안내문(`database/private.text`)과 6자리 확인 코드를 띄움 → 맞게 입력하면 **그 서버의 국가 국적**으로 가입, 기본 통화로 초기 자산 지급 | `functions/slash_commands.py: self_register`, `discord_views.py: RegistrationModal` |
| 웹 "계정 만들기" | Discord 인증을 통과한 누구나 | **목록에서 국가를 직접 고름**, 현금 **1,000,000 고정**으로 가입 | `web_api/server.py: save_password(create=True)` |

| `/설치 [국명] [화폐]` | 서버 소유자·관리자 | 운영진 전원에게 DM으로 신청을 보냄. 운영진이 **`$서버설치 …` 명령을 복사해 직접 실행**해야 반영. 신청자에게 결과 안내 없음 | `slash_commands.py: request_installation`, `admin_commands_manager.py` |

운영 DB 조회 기준(2026-11-27): 활성 회원 68명, 국가-화폐 연결 2개, **등록된 서버(`guild_countries`) 0개**. 즉 지금은 어느 서버에서도 Discord `/등록`이 되지 않고(서버가 가입돼 있지 않다는 안내만 나옴) 웹 가입만 동작하는 상태입니다.

## 2. 문제점

1. **서버 편입에 승인이 없습니다.** 서버 관리자가 기존 어느 국가에든 스스로 편입할 수 있고, 다른 국가로 바꿔 덮어쓸 수도 있습니다. 신규 가입자의 국적(=재산이 가는 국고)이 서버 관리자 손에 달려 있습니다.
2. **설치 신청이 수작업입니다.** 명령어 문자열을 복사해 실행해야 하고, 승인·거절 기록과 신청자 통지가 없습니다. 신청 DM이 실패하면 신청이 사라질 수 있습니다.
3. **명령어가 겹치고 이름이 헷갈립니다.** `/서버등록`(바로 편입)과 `/설치`(신청)는 목적이 비슷한데 규칙이 다르고, `/서버탈퇴`는 이름과 달리 "설치"를 되돌리지 않습니다.
4. **가입 경로가 둘이고 규칙이 다릅니다.** Discord는 서버 국가, 웹은 국가 직접 선택. 초기 자산은 Discord는 국가 기본 통화 기준, 웹은 1,000,000 고정(코드에 박혀 있음).
5. **가입 때 약관 동의가 기록되지 않습니다.** 모달의 안내문(`private.text`)은 공식 약관과 별도 문서라 내용이 어긋날 수 있고, 웹 가입에는 안내·동의 단계 자체가 보이지 않습니다. 동의 기록(`document_consents`)은 "개정 동의"에만 쓰입니다.
6. **탈퇴가 웹 전용입니다.** 웹 계정이 없는 Discord 회원은 탈퇴 방법이 없습니다(문의로만 가능). 서버를 떠난 회원이나 서버가 사라진 국가에 대한 처리도 없습니다.

## 3. 제안

### 설계 원칙
- 국적·국고에 영향을 주는 결정은 **운영진 승인**을 거친다.
- 가입은 **하나의 코어 함수**(`register_member`)로 모으고 Discord·웹은 입구만 다르게 한다.
- 승인·거절·동의는 **기록**하고 당사자에게 **통지**한다.
- 기존 명령어는 **전환 기간 동안 그대로** 동작시켜 운영을 끊지 않는다.

### A. 서버: 신청 → 승인 → 가입 하나의 흐름
- 새 명령 **`/서버신청`**: 이미 있는 국가에 합류하거나(국가 선택), 새 국가·화폐를 제안한다(국명·화폐 입력). 서버 소유자·관리자만.
- 신청은 DB 기록(`guild_applications`: 서버 ID·이름, 신청자, 국가·화폐, 상태, 결정자, 사유, 시각)으로 남는다. 같은 서버의 진행 중 신청은 1건만.
- 콘솔에 **"서버 신청" 화면**: 목록, 승인/거절(거절은 사유 필수). 승인하면 국가·화폐 연결과 서버 편입을 한 번에 처리하고(기존 `$서버설치` 로직 재사용), 신청자에게 **결과 DM**. `$서버설치`는 그대로 남겨 두되 같은 코어를 쓴다.
- **`/서버해지`**(현 `/서버탈퇴`): 확인 버튼 한 단계, "기존 시민의 국적은 유지됩니다"를 먼저 안내. 서버에서 봇이 추방·삭제되면 자동으로 해지하고 운영진에게 알림. 마지막 서버가 사라진 국가는 운영진에게 경고.
- 기존 `/서버등록`, `/설치`, `/서버탈퇴`는 전환 기간(예: 30일) 동안 새 흐름으로 **안내만** 하고 넘긴다. 이후 제거.

### B. 사용자 등록: 코어 하나, 입구 둘
- `register_member(user_id, nickname, country, source)` 하나가 사용자 행 생성, 초기 자산, **약관 동의 기록**, 환영 알림을 처리.
- Discord `/등록`: 서버 국가를 따름(현행). 모달 안내는 `private.text` 대신 **공식 약관·방침의 핵심 요약 + 링크**로 교체하고, 확인 코드는 유지. 제출하면 그때의 문서 개정을 동의로 기록.
- 웹 "계정 만들기": 국가 목록을 **서버가 가입된 국가만**으로 제한(지금은 연결된 모든 국가). 이용약관·개인정보 처리방침 **체크박스 동의 단계 추가**, 같은 코어 호출.
- 초기 자산은 설정값 `initial_cash`(국가별 덮어쓰기 가능)로 통일하고 1,000,000 하드코딩을 제거.
- 탈퇴 후 재가입은 현행처럼 허용(새 회원으로). 남용이 보이면 쿨다운을 설정값으로 추가.

### C. 탈퇴
- 웹 버튼은 그대로. **Discord `/탈퇴`를 추가**: 같은 `withdrawal_manager`, 두 번 확인(되돌릴 수 없음, 재산이 국고로 간다는 문구), 막히는 사유가 있으면 목록으로 안내.
- 서버를 떠난 회원은 자동 탈퇴시키지 않고 **안내만** 한다(재산 처분을 본인 동의 없이 하지 않는다).

### D. 명령어 정리 (전후)

| 지금 | 제안 |
|---|---|
| `/등록` | `/등록` (유지, 안내문·동의 기록 개선) |
| `/서버등록`, `/설치` | `/서버신청` 하나로 통합 (전환 기간 안내) |
| `/서버탈퇴` | `/서버해지` |
| (없음) | `/탈퇴` 추가 |
| `$서버설치` | 유지(운영진 바로 가기), 같은 코어 사용 |

## 4. 단계와 위험

| 단계 | 내용 | 위험·대응 |
|---|---|---|
| 1 | `register_member` 코어 + 동의 기록 + 초기 자산 설정값 + 웹 동의 단계 | 가입 경로를 건드리므로 시험 먼저. 기존 가입은 영향 없음 |
| 2 | `guild_applications` + 콘솔 승인 화면 + 결과 DM + `/서버신청`·`/서버해지` | 새 테이블은 PG 동기화로 자동 추가. 옛 명령은 그대로 둠 |
| 3 | Discord `/탈퇴` | 기존 탈퇴 코어 재사용, 막힘 목록 시험 |
| 4 | 옛 명령 안내 전환 → 제거, 문서·도움말·약관 갱신 | 약관 변경은 개정 공지 절차(모든 채널·비교문) 적용 |

탈퇴 관련 새 테이블에는 `COLUMN_BUCKETS` 분류를 함께 넣습니다(사용자 ID 열이 있는 경우).

## 5. 정해 주실 것 (저의 추천 포함)

1. 기존 국가에 **합류**하는 서버 신청도 운영진 승인이 필요한가? → **추천: 필요**(국적=국고가 걸려 있음).
2. 웹 가입 국가 목록을 **서버가 있는 국가로 제한**해도 되나? 현재 서버가 0개라 제한하면 **웹 가입이 막힙니다**. → **추천: 첫 서버 승인 후 켜기**(설정 스위치).
3. 초기 자산 기본값은 1,000,000(국가 기본 통화 단위)을 유지? 국가별로 다르게 할 필요가 있나?
4. 옛 명령 전환 기간: **30일** 괜찮은가?
5. 서버를 떠난 회원은 **안내만** 하고 자동 탈퇴는 하지 않는 안으로 괜찮은가?
6. Discord `/탈퇴`는 웹 계정이 없는 회원도 쓸 수 있게 해도 되나? → **추천: 예**.

## 6. 이번 제안에서 하지 않는 것
- 국가 생성·삭제 규칙, 국고 정책, 귀화 절차 변경
- 이미 가입한 회원의 국적·자산 변경
- 약관 문구 자체의 개정(구현 단계에서 위 변경을 반영할 때 별도 개정 절차로 진행)

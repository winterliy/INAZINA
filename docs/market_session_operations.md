# 시장 정지와 사건 가격 경로

시장 상태는 `database/inazina.db`의 `market_session` 한 행에 저장합니다.
봇이 재시작해도 휴장·일시정지 상태와 자동 재개 시각을 유지합니다.

| 관리자 명령어 | 동작 | 재개 |
|---|---|---|
| `$휴장` | 신규 매수·매도·옵션 작성·펀드 가입/환매와 자동 가격 변동 정지 | `$개장` |
| `$개장` | 거래와 자동 가격 변동 재개 | 즉시 |
| `$장일시정지` | 거래와 자동 가격 변동 일시정지 | `$장재개` |
| `$장재개` | 거래와 자동 가격 변동 재개 | 즉시 |
| `$서킷브레이커 1` | 거래와 자동 가격 변동 정지 | 20분 후 자동 |
| `$서킷브레이커 2` | 거래와 자동 가격 변동 정지 | 20분 후 자동 |
| `$서킷브레이커 3` | 거래와 자동 가격 변동 정지 | 다음 한국시간 날짜의 00:00에 자동 |
| `$사이드카` | 거래와 자동 가격 변동 정지 | 5분 후 자동 |

이 게임은 모든 신규 시장 거래를 함께 정지합니다. 서킷브레이커를 자동으로
발동하는 지수 등락률 규칙은 추가하지 않았으며, 관리자가 명령어로 발동합니다.
3단계의 익일 00:00 재개는 이 게임의 운영 규칙입니다.

이미 휴장한 시장에는 사이드카·서킷브레이커를 적용할 수 없습니다.
수동 일시정지에도 자동 재개를 덧씌우지 않습니다. 자동 정지 중에는 더 긴
정지로 연장할 수 있지만 더 짧은 정지를 적용해 기존 정지를 단축하지 않습니다.
관리자가 `$개장`·`$장재개`를 실행하면 예약된 재개를 기다리지 않고 즉시 재개합니다.

정지 중 기존 주문은 유지합니다. 주문 취소·예약금 환불·계약 만기 정산·
대출 상환·통장 이자 처리는 계속할 수 있습니다. 선물의 만기 전 시가평가와
기존 주문 자동 체결은 정지하고, 만기 정산은 계약 만기에 그대로 진행합니다.
옵션·채권·대출의 계약상 만기는 시장 정지 때문에 연장하지 않습니다.

자동 가격·시장 공통 충격·GARCH 모델·가격/지수 로그는 정지 중 갱신하지 않습니다.
한국시간 날짜 변경에 따른 전일 Movement 로그 정리는 정지 중에도 계속합니다.
사건과 자동 목표가격의 진행 시간은 정지 기간만큼 뒤로 이동합니다.
예를 들어 60초 사건이 10초 진행한 뒤 300초 정지했다면 재개 후 남은 50초 동안
진행합니다. 정지 중 새로 만든 사건은 재개할 때부터 진행합니다.
이미 지나간 자동 재개 시각은 재시작 시 한 번 처리하며, 같은 정지 기간이
중복 적용되지 않습니다. 이력은 `admin_audit`에 남습니다.

## 사건 가격 변동

사건 가격의 기준선은 다음과 같습니다.

`기준가격 = 시작가격 + (목표가격 - 시작가격) × 진행시간 / duration`

실제 가격은 이 평균 변화율 기준선을 중심으로 위아래로 움직입니다.
GARCH 공통·종목 충격은 유지하며, 충격에 따른 편차를 약 3초의 완화 속도로
연결합니다. 한 번의 충격이 시작가격과 목표가격 사이 전체를 뛰어넘지 않도록
편차를 제한했습니다.

- 최대 기본 편차 폭은 `max(전체 목표 변화폭 × 12%, 기준가격 × 2%)`입니다.
- 이 폭은 기준가격의 10%를 넘지 않으며, 모달의 변동률 0~100%를 곱합니다.
- 시작·종료 지점에서는 편차 폭이 0으로 줄어들고, duration 끝에 목표가격에 도달합니다.
- 변동률 0%에 목표가격을 지정하면 기준선을 그대로 따라갑니다.
- 사건 교체는 변경 시점의 현재가격을 새 출발점으로 삼습니다.

선형 기준선 주변의 변동이고, 가격을 일정하게 유지하는 설정은 아닙니다.
사건이 완료된 다음에는 기존 GARCH·자동 목표가격 알고리즘이 이어집니다.

## 코드에서 사용하는 API

`MarketSessionManager(db).control(actor_id, action, stage=None, now=None)`는
`close`, `open`, `pause`, `resume`, `circuit`, `sidecar`를 지원하고 `(성공여부, 메시지)`를 반환합니다.

`process_due(now=None)`와 `get_state(now=None)`는 자동 재개를 처리한 상태를 반환합니다.
`trading_error(conn=None, now=None)`는 거래 가능하면 `None`, 정지 중이면 안내 문구를 반환합니다.
금액·수량을 변경하는 거래에서는 같은 원자적 트랜잭션의 `conn`을 전달해야 합니다.

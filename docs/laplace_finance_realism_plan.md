# LAPLACE 금융 시뮬레이터 현실화 계획

목표는 실제 금융기관 운영 시스템이 아니라 현실 요소를 갖춘 금융 시뮬레이터다. 기존 기능과 데이터 구조를 최대한 재사용하며, 겹치는 기능은 재작성하지 않고 확장한다. 기준금리 결정권은 관리자에게 둔다.

## 보안·준법 작업 흐름

웹 로그인은 Discord OAuth, 서명 세션 쿠키, 비밀번호 해시 및 로그인 제한 기반이 있다. `admin_audit`에는 관리자 작업이 append-only로 기록되고 KYC/AML 검토에도 별도 불변 이벤트 이력이 있다. KYC는 실명·신분증·증빙 원본 없이 상태·위험등급·고정 사유 코드만 보존한다. AML은 국가별 운영 임계치 설정, 거래 고액·24시간 누적액·횟수 경보, 사례 상태 이력을 추가했다. 임계치는 기본 비활성이고 운영자가 시뮬레이터 정책으로 설정하며, 법정 기준이나 법적 신고 판정이 아니다. 인증 관리자 전용 `/internal/admin/compliance` API와 대시보드에서 KYC 검토, AML 규칙 설정·사례 검토와 최근 이벤트 조회가 가능하다. 보존/열람 정책·심사 준비용 통제 증빙은 남아 있다. 실사용 신분증 원본은 목적·관할·보존기간·접근통제를 정하기 전에는 수집하지 않는다.

## 순서와 최소 변경 원칙

1. 기존 테이블·서비스를 재사용해 기대신용손실을 연결한다.
2. 기존 기관 손익원장을 유지하며 불변·균형 검증을 갖춘 상품화폐 최소단위 은행 분개장을 병행 구축하고, 거래 유형별로 점진 연결한다.
3. 조달원, 자본, 유동성, ALM 규제를 기존 `financial_institutions`와 기관 원장에 확장한다.
4. 거시·시장 입력과 금리곡선의 전달·대체 규칙을 추가한다.
5. 기존 차주·담보·계약 흐름에 리스크 등급, 법률·세금 규칙, 채무조정을 연결한다.
6. 예금보험·은행정리 및 외화위험을 기관 건전성 모델에 통합한다.
7. 채권 위험지표와 금리 파생·헤지를 기존 시장 인프라 위에 추가한다.
8. 보안 검토 후 KYC·AML·공통 감사로그 및 규제 심사 증빙을 연결한다.
9. 금리·예금인출·대량부도·환율 스트레스, 회계 불변식과 국가별 규칙 검증을 완료선으로 둔다.

주식예탁증서(DR)는 [GitHub issue #80](https://github.com/winterlies/INAZINA/issues/80)의 별도 자산 유형으로 기존 주문·자산 시스템에 연결한다. 게임 내 정수 원주 예탁/DR 발행과 풀링 원주 상환 원장은 구현하지만 실제 예탁기관·수탁사 보관 증명은 제공하지 않는다.

## 첫 적용: 기대신용손실(ECL)

차주 신용점수, 기존 DTI·DSR, 연체·납부 이력, LTV, 기존 담보를 사용해 설명 가능한 12개월 PD와 LGD를 산출한다. 정상 상태에는 12개월 ECL, 연체·상환위험 급증 등은 계약기간 ECL을 적용한다. 국가별 낙관·기준·하방 시나리오의 확률과 PD/LGD 배수는 `credit_risk_scenarios`에서 조정한다. 일별 평가를 `loan_ecl_assessments`에 보존하고, 충당금 증감은 기존 `financial_institution_ledger`를 통해 기관 자기자본에 반영한다. 부도 시 기존 충당금과 실제 회수 후 손실의 차이만 손익에 반영한다.

이 1차 모델은 시뮬레이터용 점수카드다. 감독기관 승인 모델이나 실제 신용평가 모형으로 간주하지 않는다. 평가 기록은 보존되고 충당금 증감은 기관 손익원장과 은행 분개장에 연결되며, 뒤의 거시 시나리오·모형 검증 작업에서 입력을 정교화한다.

## 진행 메모

- ECL의 국가별 확률가중 시나리오와 충당금 변동 회계 연결을 추가했다.
- 부도 상태 대출도 ECL 대상에 포함하고 Stage 3 및 100% 부도확률로 분류한다. 이는 시뮬레이터 정책이며 회계기준 승인 모델은 아니다.
- 관리자 은행 원장 웹 화면에 기존 대출 만기와 예금 상품 계약기간을 사용한 통화별 계약상 만기갭(1·7·30·90·365일 및 초과)을 추가했다. 이는 대출 유입과 예금 유출의 단순 ALM 보조지표다. 행동만기·조기인출·장부외 흐름·시장성 자산/조달·LCR/NSFR은 포함하지 않으며 규제비율이 아니다.
- `bank_journal_entries` / `bank_journal_lines`는 차변·대변 합계가 통화 최소단위로 일치해야 전기되며, 전기 후 수정·삭제·추가를 차단한다.
- 은행 분개 불균형 감사 조회의 SQLite `HAVING` 절을 집계식으로 비교하도록 수정해, 균형 분개가 행 단위 차변·대변 비교 때문에 오탐되던 문제를 해결했다.
- 1차 연결 이벤트는 예금 개설·해지, 대출 실행·상환, 예금·대출 이자, ECL 충당금 변동, 은행 계좌가 관여한 송금 입·출금이다. 예금 해지는 같은 기관 내 계좌이체를 구분하고, 조기해지 페널티와 IMA 추가지급을 별도 계정으로 기록한다. 분개장에 시산표와 불균형 감사 조회를 제공한다. 기존 기관 손익원장은 하위호환을 위해 아직 병행한다.
- 송금에서는 실제 출금된 은행 계좌별 출금과 은행 계좌 입금을 거래 식별자에 연결했다. 환전 송금은 원천·목적 통화별 균형은 기록하지만 환전 청산계정·환차손익·국고 수수료 대사는 아직 남아 있다.
- 부도 전 ECL 충당금을 부도손실충당금으로 대체하고, 담보회수·추가손실·충당금 환입을 분개한다. 부도 후 회수금도 대출채권 감소, 충당금 환입, 회수수익으로 나눈다.
- 기관 손익원장과 같은 거래 참조의 은행 분개 P&L을 통화별로 대사하는 조회를 추가했다. 이전 거래나 아직 연결하지 않은 이벤트는 `missing_journal`로 표시한다.
- 인증된 관리자 전용 `/internal/admin/bank-journal?issuer=...&currency=...&since=...` 읽기 API와 웹 대시보드의 은행 원장 화면에서 통화 정밀도로 표시된 시산표, 게시된 불균형 분개, 기관 손익원장 대사를 조회할 수 있다. 조회만 제공한다. 준법 화면의 ECL 노출액·기대손실도 대출 상품통화 자릿수로 표시한다.
- KYC 상태 변경은 개인정보 원본 없이 사유 코드 중심으로 append-only 이력에 기록한다. AML은 국가 통화 기준의 고액·24시간 누적액·횟수 임계치를 설정할 수 있고, 설정된 거래는 차단 대신 사례 경보를 만든다. AML 사례 변경도 append-only 이벤트로 보존한다.
- 다음은 일반 입출금, 외화청산·수수료의 계정 구분, 실제 누락 이벤트 연결이다. 대손충당금 모델은 아직 시뮬레이터용이며, 실제 회계·감독 기준 완전 준수로 볼 수 없다.
- KYC 상태·AML 규칙·AML 사례 변경은 활성 관리자 역할을 요구하며, 관리자 전용 API와 대시보드 화면에서 조회·검토할 수 있다. 만료된 확인 완료 KYC는 관리자가 명시적으로 실행해 최대 500건씩 만료 처리할 수 있고, 건별 이력·감사 작업을 남긴다. 업무 큐와 각 이벤트 이력은 최근 100건으로 제한하고 신분증·실명·자유기술형 증빙은 노출·저장하지 않는다. 운영 보존·열람 정책, 규제 심사 증빙과 실제 규제 준수는 아직 미완료다.
- `admin_audit`의 수정·삭제를 DB 트리거에서 차단하고 대시보드도 읽기 전용으로 바꿨다. 감사 기록 보존기간·접근로그·암호화 백업 정책은 아직 정해야 한다.
- DR은 `depositary_receipts` 메타데이터와 `market_assets` 자산으로 생성하고, 외화 공통 주문장과 기존 가격·배당을 재사용한다. `/dr전환`과 웹 HTS는 사용자의 예약되지 않은 정수 원주를 시뮬레이터 보관 원장으로 옮겨 DR을 발행하고, 보유 DR 상환 시 풀링 원주를 돌려준다. 중복 방지 참조값과 불변 이동 이력을 보존하며, 웹 HTS는 불확실한 요청의 참조값을 세션에 유지해 재시도 중 중복 발행을 막고 사용자는 본인 전환 이력을 조회할 수 있다. 이는 실제 수탁기관의 보관 증빙이 아니다.
- DR 프로그램 메타데이터를 관리자 종목 API·대시보드와 Discord·HTS 종목 정보에 노출하며, 웹 HTS에서 사용자가 DR 발행·상환·본인 이력 확인을 할 수 있다. 관리자 대시보드에는 최근 100건의 불변 DR 전환 원장도 제공한다. 시뮬레이터 보관 원주와 미상환 DR 기준 필요량, 현재 환율로 환산한 단순 참고가와 가격 괴리도 표시한다. 같은 통화의 활성 DR 보유자에게 기초 원주의 정기·특별배당 권리를 비율대로 전달한다. 이는 시뮬레이터 내 권리 전달이며 실제 수탁 증빙이 아니고, 타 통화 DR의 배당 환전·수수료·세금·유동성·의결권 차이는 아직 반영하지 않는다.
- DR 괴리 모니터는 관리자 웹 상품 화면이 열려 있는 동안 1분마다 표본 수집 요청을 보내고, 종목별 최대 5분에 한 번 `dr_deviation_samples`에 기록한다. ±10% 경보 상태의 진입·해제·방향전환을 append-only `dr_deviation_alert_events`에 남기며 표본은 90일 보관한다. 이 기록은 대시보드 화면이 닫혀 있으면 수집되지 않는 관측 이력이고, 별도 알림 전송·거래중단·가격보장 기능이 아니다.
- 기초주식의 주주명부를 마감할 때 동일 결제통화의 활성 DR 보유량 × DR당 원주 수를 원주 등가 수량으로 더해, 기존 원주 배당 지급 흐름에서 함께 배당한다. 외화 통화가 다른 DR은 현재 산정에서 제외한다. 실제 예탁기관 수수료·원천징수 협약과 교차통화 배당정산 원장은 후속 과제다.
- HTS와 관리자 상품 화면은 원주·전환비율·환율로 계산한 DR 단순 참고가와 현재 괴리를 표시한다. 괴리가 ±10% 이상이면 정보성 경보를 보이며, 이는 거래중단·가격보장 기준이 아니다. 관리자 화면에서는 최근 표본과 경보 상태전환 이력을 조회할 수 있다.

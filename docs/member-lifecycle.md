# 회원 탈퇴, 약관 개정 동의, 서비스 화면

2026-11-25에 추가된 기능의 동작과 운영 방법입니다. 공개 문서(이용약관·개인정보 처리방침)의 내용은 `apps/site/public/links/`에 있습니다.

## 1. 회원 탈퇴
- 나루와 콘솔의 "내 계정" 맨 아래 "회원 탈퇴" 버튼 → 확인 창 한 번 → 즉시 탈퇴합니다. 일반 회원(`role=user`)만 가능하고, 관리자·국가·법인 계정과 대리 로그인은 불가능합니다.
- API: `POST /api/me/withdraw` (본문 `{"confirm": true}`) → 내부 `/internal/me/withdraw` → `managers/withdrawal_manager.py`.
- 하는 일(한 트랜잭션): 미체결 주문 취소 → 이자 정산 → 은행 계좌를 닫아 잔액을 현금에 합산 → 현금을 국적 국고로 이전 → 보유 주식을 국고 보유분에 합산 → 대출·국채·복권을 국고로 이전 → 개인정보 삭제(웹 로그인, 알림, 게시판 글·댓글·좋아요·설문·신고, KYC, 차트 설정) → 나머지 기록의 사용자 ID를 임의 ID(`w-…`)로 교체 → `withdrawal_records`에 디스코드 ID와 임의 ID의 대응을 1년간 보관.
- 막히는 경우(운영진이 정리): 선물, 옵션, ELS, 스왑, 펀드 계좌, 법인 지분, 도산 절차, DR 보관, 담보가 있는 대출, 처리 중인 귀화·정산, 받지 못한 우선주 배당 등(`BLOCKERS`와 `NationalityManager.blockers`).
- 변경이 막힌 감사 테이블(신용 이벤트, 신용점수 이력, 현금·송금 기록, 체결 감사, 지갑 조정, 실현손익)은 트리거 때문에 ID를 바꿀 수 없어 디스코드 ID가 남습니다. 개인정보 처리방침에 명시되어 있습니다. 어떤 열이 남았는지는 결과의 `retainedAuditColumns`에 기록됩니다.
- 대응표(`withdrawal_records`)는 서버의 정기 정리 작업(`web_api/server.py`, 한 시간 간격, 웹 요청이 있을 때 실행)에서 1년이 지나면 지웁니다. 게시판 첨부 파일은 같은 정리 작업이 행이 없는 파일을 지웁니다.
- **규칙:** 사용자 ID를 담는 새 테이블이나 열을 만들면 `COLUMN_BUCKETS`(transfer / block / delete / rekey / staff)에 함께 넣어야 합니다. 점검 시험(`tests/test_withdrawal.py`)은 시험 DB에 이미 있는 테이블만 검사하므로, 게시판처럼 필요할 때 만들어지는 테이블은 운영 DB와 가끔 대조하세요.

- **Discord `/탈퇴` (2026-11-27):** 같은 탈퇴 처리를 디스코드에서도 합니다. 명령을 실행하면 먼저 막히는 사유(`blockers`)를 확인해 있으면 목록으로 안내하고, 없으면 모달로 한 번 묻습니다(귀속될 국고·취소될 주문·해지될 계좌 안내 + '탈퇴' 입력). 입력이 맞아 제출되면 탈퇴하고 본인에게만 결과를 알립니다. 개정 동의를 아직 안 한 회원도 탈퇴는 할 수 있습니다(`_prepare`를 거치지 않음). 코드: `functions/slash_commands.py: leave_service`, `functions/discord_views.py: WithdrawalModal`.

## 2. 불리한 약관 개정의 동의
- 콘솔 "문서 · 약관"에서 약관/방침 등을 저장할 때 "이용자에게 불리하거나 중요한 변경"을 체크하면(공지 30일): 서버가 동의 요청(`document_consent_campaigns`, `document_consents`)을 만들고, 봇이 모든 일반 회원에게 변경된 부분과 "동의합니다" 버튼을 DM으로 보냅니다(`functions/consent_views.py`, 20초마다 확인). 개정안을 취소하거나 다시 저장하면 이전 요청은 닫힙니다.
- 버튼은 영구 버튼(`ConsentButton`, `consent:<번호>`)이라 봇을 재시작해도 동작합니다. 동의는 처음 시각만 기록합니다.
- 시행일이 지난 뒤에도 동의하지 않은 회원: 슬래시 명령어는 동의 안내(버튼 포함)로 막히고(`/도움말`, `/등록` 제외), 웹은 `identity()`가 `403 consent_required`를 돌려줘 나루와 콘솔이 동의 화면(`apps/shared/ConsentGate.tsx`)을 보여 줍니다. 열려 있는 경로는 세션 정보, 동의, 탈퇴, 로그인·로그아웃뿐입니다(`DocumentConsent.path_is_exempt`). 시행 후에 등록한 회원과 관리자, 대리 로그인은 해당하지 않습니다.
- 동의 기록(`document_consents`)은 탈퇴 시 임의 ID로 바뀌어 보관됩니다.

## 3. 콘솔 "서비스" 화면과 로그
- 콘솔 운영 → 서비스(관리자 전용, 읽기 전용): 서비스 포트 상태, 설정값(비밀값 제외), 서비스별 로그 끝부분.
- `start_all`이 각 서비스의 출력을 터미널과 `logs/<서비스>.log`에 함께 남깁니다(5MB가 넘으면 다음 시작 때 `.log.1`로 옮김). `logs/`는 git에서 제외됩니다.
- API: `GET /api/admin/ops`, `GET /api/admin/ops/log?service=…&lines=…`.

## 4. 봇의 전역 명령어
- 모든 슬래시 명령어를 **전역**으로 등록합니다(2026-11-27 변경). 앱 프로필의 "명령어" 칸에는 전역 명령어만 보이기 때문입니다. 예전에 서버별로 등록했던 사본은 시작할 때 지워서 중복으로 보이지 않게 합니다. `/약관`을 뺀 모든 명령어는 서버 안에서만 쓸 수 있게(guild-only) 표시합니다(`functions/command_sync.py`).

## 5. 모든 개정은 모든 채널로 공지 (2026-11-26)
- 콘솔 "문서 · 약관"에서 약관·방침·운영규칙·내부규칙을 **확정**하면 `web_api/announcements.py`가 개정 공지를 하나 만들고 같은 내용을 모든 곳에 냅니다. 알림 중요도 구분은 없고 모든 개정이 같은 방식으로 나갑니다.
  - **변경 전·후 비교**(신구 대조: 바뀐 조항만 조항 제목 아래 "변경 전 / 변경 후"): 날짜 줄(시행일·개정)은 비교에서 제외합니다.
  - **나루 알림창**: 회원 모두에게 1건(공지 때, 시행일, 취소 때 각각). 디스코드 중복 발송을 막으려고 `discord_sent`로 표시합니다.
  - **나루 공지 게시판 글**: 작성자는 "관리자"로 표시(`board_posts.author_label`, 실제 작성한 관리자는 DB에만 남음).
  - **공식 사이트**: `links/notices.json`을 쓰고 자동 게시 → `/notices/` 공지 페이지(비교표), 홈의 "개정 예정" 띠, Atom 피드(`feed.xml`), 사이트맵.
  - **나루 첫 화면 모달**: 로그인한 회원에게 아직 못 본 공지를 한 번 보여 주고(`announcement_seen`), 불리한 변경이면 "지금 동의하기" 버튼으로 DM과 같은 동의를 합니다. 시행일에 한 번 더 보여 주며 2주 뒤에는 더 보이지 않습니다. 모달의 "개정 안내 전체 보기"와 알림은 나루 `/announcements` 페이지로 갑니다.
  - 불리한 변경은 기존처럼 DM과 동의 버튼, 시행일 이후 미동의자 이용 제한이 따릅니다. 모든 공지에 "DM에서 동의해야 시행일 이후에도 서비스를 계속 이용할 수 있다"는 안내가 들어갑니다.
- **초안과 확정 분리**: 콘솔 저장은 공개 발표입니다(공개 GitHub에 즉시 올라가고, 취소해도 이력이 남음). 그래서 문구를 다듬는 동안은 "초안 저장"(이 컴퓨터의 `database/document_drafts/`, 공개되지 않음)을 쓰고, 확정할 때 경고 확인 창이 한 번 더 나옵니다. 확정하면 초안은 지워집니다.
- 개정 공지 기록 테이블: `document_announcements`(저장한 관리자 `actor_id` 포함, 공개 목록에는 나가지 않음), `announcement_seen`(탈퇴 분류표에 등록됨).

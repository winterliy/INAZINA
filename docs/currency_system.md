# 국적과 화폐

등록 서버 ID는 `guild_countries.guild_id`, 국적은 `guild_countries.nationality`로 설정한다.
국가 ID(사용자의 `nationality`)와 국가별 기본 통화 연결은 `country_currencies`에 저장하고, 통화 기준정보는 `currencies`에 둔다. 통화 목록에서 해당 통화를 사용하는 국가는 `country_currencies`를 통화 코드로 묶어 표시한다. 이 관계를 `currencies`에 중복 문자열로 저장하지 않아 국가나 통화 설정 변경 시 목록이 어긋나지 않는다. 모든 통화 참조에는 `currencies.code`를 사용한다.

`currencies`는 통화 코드·표시명·상태·기준 환율·소수 자릿수와 선택적 시장 자산(`asset_code`)을 정의한다. `market_assets`는 가격·거래·주문·차트 이력을 갖는 시장 상품이다. 예를 들어 USD는 통화 기준정보이고 `FX_USD`는 USD/NWX 시장 시세 상품이다. 시장 상품이 없는 통화는 `reference_rate`를 사용한다.
서버 관리자는 `/설치 [국명] [화폐]`로 신청한다. INAZINA 등록 여부와 관계없이 서버 소유자 또는 Discord 관리자 권한을 가진 사람만 신청할 수 있다.
신청 시 INAZINA 관리자(DB role=admin 및 초기 관리자)에게 발신 서버 ID·국명·화폐·신청자와 승인 명령어를 DM으로 전달한다. 신청만으로 국적 설정이 적용되지는 않는다. DM 전달 실패 시 신청자에게 실패를 알린다.
INAZINA 관리자 승인: 해당 서버에서 `$서버설치 낙원 NWX` / `$서버설치 A국 AAA`. 신청 DM을 받은 관리자는 서버 ID를 포함해 `$서버설치 123456789 낙원 NWX`로 설정한다.
등록하지 않은 사용자는 해당 서버에서 `/등록`한다. 국적과 `users.registration_guild_id`를 처음 등록할 때 저장하며 다른 서버를 이용해도 바뀌지 않는다.
DM에서 신규 시민을 등록하려면 등록 서버 정보가 없으므로 서버에서 실행해야 한다. 기존 시민의 조회·거래는 DM에서도 가능하다.
기존 시민의 국적과 현금은 이전 값 그대로 보존한다. 국가 화폐 연결이 없는 기존 시민만 `settings.default_currency`(초기 NWX)를 사용한다.

## 현금·외환

국적 화폐가 기본화폐이며 그 외 모든 화폐는 외환이다. A국 시민에게 NWX도 외환이다.
`users.cash`는 기존 NWX 현금의 저장소이며 NWX가 모든 시민의 기본화폐라는 뜻은 아니다.
다른 통화의 현금은 `currency_wallets(user_id,currency_code,balance_units)`에 저장한다. 금액은 100만분의 1 단위의 정수다.
외환통장 예금은 기존 `fx_accounts`에 별도로 남으며 현금과 중복 합산하지 않는다.
`/내지갑`의 메인 요약은 본인 기본화폐로 평가하고, 통화별 현금에서 각 화폐의 실제 잔액을 표시한다.
지갑의 NWX 평가액·상세 금액도 본인의 기본화폐로 환산해 표시한다. 외환 잔액과 시장 호가·차트·환전·송금 양쪽 금액은 실제 대상 통화를 유지한다. NWX라는 글자만 바꾸어 잘못된 액수를 표시하지 않는다.
`/송금`은 기본 출금 시 본인 기본화폐 지갑, 사용자 ID 수신 시 수신자의 기본화폐 지갑으로 송금한다.
출금계좌 자동완성에서 다른 화폐의 지갑도 선택할 수 있다. 기존 통장 계좌번호로 직접 입출금할 수도 있다.
`/환전`은 지갑 현금을 환전할 수 있다. 대상 통화의 통장이 있으면 기존 통장으로 입금하고, 없으면 해당 화폐 지갑으로 입금한다. 출금은 지갑 잔액을 먼저 사용하며 부족할 때 같은 화폐 통장 잔액을 사용한다.
본국 화폐의 주식·현물은 본국 현금 지갑으로 거래할 수 있다. 충분한 예치금이 있는 해당 화폐 통장이 있으면 그 통장을 사용한다. 주문 취소 시 동일 지갑에 예치금을 돌려준다.

## 기본소득

`$기본소득 10000 NWX`는 지급 당시 환율로 1인당 10000 NWX 상당액을 각 시민의 기본화폐로 지급한다.
통화를 생략하면 관리자 본인의 기본화폐를 사용한다. 국고에서는 지급 기준 통화로 총 재원을 차감한다.
예: `$환율수정 NWX AAA 3` 설정 후 낙원 시민은 10000 NWX, A국 시민은 30000 AAA를 받는다.
정부 지급에는 환전 수수료가 없다. 통화별 최소 단위 미만은 버리며 지급액이 0이 되거나 환율 오류가 있으면 전체 지급을 취소한다.
`basic_income_payments`는 지급 묶음 ID, 원화폐·수령화폐, 원액·지급액, 당시 양쪽 환율, 지급시각을 보존한다.

## 상품 통화와 환율

`company`, `investment`, `market_assets`, `saving`, `liability`, `treasury_bond_products`, `option_contracts`의 `quote_currency`가 가격·계약금액의 통화 코드다.
`fx_products.currency_code`는 외환 예금 통화다. 계좌·대출·주문에도 통화 코드가 따로 저장된다.
기존 상품·계약은 NWX를 유지하며, 발행 후 통화를 바꾸어 기존 계약을 재표시하지 않는다.
상품생성의 선택 JSON에 `{"quote_currency":"USD"}`를 쓸 수 있다. 외화 거래 지원 유형은 현재 주식·현물이며 다른 유형은 NWX 계약 검증을 유지한다.
`currencies.reference_rate`는 시세 상품이 없는 통화의 양수 기준값(문자열, 정확한 분수도 허용)이다. 시세 상품이 있으면 가격을 기준값으로 사용한다.
`currencies.rate_multiplier`는 그 기준값에 곱하는 양수 비율이다. 통화 간 환율은 두 기준값의 비율이며 소수 환율도 유지한다.
환율에는 `currency_liquidity_state`의 유동성 보정도 적용된다. 기준 공급량보다 발행·예치 총량이 늘면 해당 통화 가치는 완만하게 낮아지고, 국고 밖 유통 비율이 기준보다 줄면 추가로 낮아진다. 총량과 유통비율이 기준점과 같으면 보정값은 1이다.
총량은 해당 화폐의 지갑 잔액과 외환통장 잔액의 합계이며, NWX는 현금·일반계좌 잔액의 합계다. 국고 보유분은 총량에는 포함되지만 유통량에서는 제외한다. 신규 통화는 최초 발행 시의 총량·유통비율을 기준점으로 자동 기록한다.
DB Browser에서 `currency_liquidity_state`의 `issuance_elasticity`, `circulation_elasticity`, `min_multiplier`, `max_multiplier`를 조정할 수 있다. 기본값은 발행량 민감도 0.50, 유통 민감도 0.20, 보정 범위 0.25~4.00배다.
`$환율수정 A B 3`은 A 기준값을 유지하고 B 값을 조정해 1 A = 3 B를 만든다. 시세 상품이 있는 B는 가격 배수를 설정하므로 이후 자동 가격변동·사건도 계속 반영된다.

## 화폐별 자릿수

`currencies.decimal_places`에 0~6을 저장한다. NWX·KRW·JPY는 초기 0, USD·EUR·GBP 등은 초기 2, 다른 통화는 6이다.
`$상품수정 USD currency 달러 FX_USD 미국 '{"decimal_places":2}'`처럼 선택 JSON으로 바꿀 수 있으며 DB Browser로도 조절 가능하다.
통화별 금액 입력은 해당 자릿수까지만 허용하며 환산 지급은 수령 화폐의 최소 단위로 절삭한다. 표시에는 지정 자릿수를 사용한다(예: USD 12.50, KRW 12500).
기존 외환통장의 이자 소수 잔액은 보존하고 화면에서만 통화별 자릿수로 표시한다.

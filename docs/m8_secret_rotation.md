# 토큰·비밀 교체 절차

대상: `INAZINA_INTERNAL_TOKEN`(대시보드·API와 파이썬 서버 사이의 인증), Discord 봇 토큰, DB 비밀번호가 있다면 그것. 값은 이 저장소, 로그, 기록 파일에 적지 않는다. 기록하는 것은 이름과 교체 날짜뿐이다.

## 주기
180일마다, 그리고 유출이 의심되거나 접근 권한이 있던 사람이 떠났을 때. '통제 · 복구' 화면이 기록이 없거나 180일을 넘기면 '교체 기한'으로 경고한다.

## 교체 순서 (내부 토큰 예)
1. 새 값을 만든다: `python -c "import secrets; print(secrets.token_urlsafe(48))"` (화면에 나오므로 터미널 기록을 남기지 않는다. 32자 이상).
2. 값을 쓰는 곳을 모두 파악한다: 웹 API 프로세스와 파이썬 서버 프로세스의 환경변수 `INAZINA_INTERNAL_TOKEN`. 두 쪽이 같은 값이어야 한다.
3. 두 프로세스를 같은 시각에 새 값으로 재시작한다(서버 재시작 절차는 사용자 승인 사항). 재시작 사이에는 내부 호출이 401로 거절된다.
4. 확인: 관리자 화면이 열리고 로그인되는지, `curl`로 토큰 없이 `/internal/...`를 부르면 401인지 본다.
5. 옛 값을 쓰던 셸 기록, 임시 파일, 메신저에 남은 사본을 지운다.
6. 기록: `python tools/secret_rotation_check.py --record INAZINA_INTERNAL_TOKEN`(오늘 날짜만 `docs/m8_records/drills.json`에 추가된다). 착륙은 `tools/land_commit.py`로 한다.

## 점검
`python tools/secret_rotation_check.py`: 환경의 토큰 길이(값은 출력하지 않음), `logs/*.log`와 추적 파일의 자격증명 패턴(`functions/secret_patterns.py`), 마지막 교체 날짜를 확인하고 하나라도 문제면 종료 코드 1이다. 서버 재시작·큰 반영 뒤의 정기 점검에 포함한다.

## 한계
이 도구는 알려진 형식의 비밀만 찾는다. 값을 직접 교체해 주지 않고, 두 프로세스의 값이 일치하는지는 확인하지 못한다(재시작 뒤 4번의 동작 확인으로 본다).

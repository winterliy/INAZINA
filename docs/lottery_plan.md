# Inazina 복권 기획안

아래는 최초 복권 기획이다. 현재는 OS 난수와 사전 약속 해시를 사용하는 1차 버전의 발권·자동 추첨·세금·지급·이월 기능을 구현했다. 실제 명령어와 운영 방법은 [복권 운영 안내](lottery_operations.md)를 따른다. 외부 독립 난수 공급자는 아직 연결하지 않았다.

## 제안 규칙

게임 NWX로 구매하는 주간 번호형 복권을 제안한다. 한 장 1,000 NWX, 1~45 중 중복 없는 번호 6개를 고른다. 자동 선택도 제공한다. 매주 토요일 20:00 한국시간에 판매를 마감하고 20:05에 당첨번호 6개와 보너스 1개를 추첨한다. 구매할 때 회차와 마감시간을 명시한다. 1인당 회차별 최대 100장으로 시작한다.

판매대금의 70%를 상금 풀, 20%를 국고, 10%를 운영 준비금으로 배분한다. 준비금은 별도 장부에 남기고 관리자가 임의로 상금 풀과 혼용하지 않는다. 1등 미발생 회차의 1등 풀은 다음 회차로 이월한다. 이월액은 신규 판매대금과 구분해 공시한다. 초기 상금 보장은 설정하지 않고 실제 적립액 안에서 지급한다.

| 등수 | 조건 | 해당 등수 풀 배분 |
|---|---|---:|
| 1등 | 본번호 6개 | 50% |
| 2등 | 본번호 5개 + 보너스 | 10% |
| 3등 | 본번호 5개 | 15% |
| 4등 | 본번호 4개 | 15% |
| 5등 | 본번호 3개 | 10% |

각 풀을 당첨 장수로 균등 분배한다. 같은 사용자의 여러 당첨 장은 각각 한 장으로 계산한다. 정수 NWX 나눗셈 잔액은 해당 풀에 남겨 이월한다. 2~5등 당첨자가 없을 때도 해당 등수 풀만 다음 회차로 이월하도록 하면 지급액이 쉽게 검증된다. 상금에 기존 게임 세율을 적용하고 원천징수 내역을 분리한다. 1등 확률은 1 / C(45,6) = **1 / 8,145,060**이다. 이월 효과를 제외한 장기 평균 총 지급액은 판매액의 70%로 설정되며, 당첨은 보장하지 않는다.

## 사용자 흐름

`/복권구매` → 회차·가격·잔액 안내 → 수동 번호 또는 자동 선택 → 확인 화면 → 원자적으로 잔액 차감·발권. 발권 성공 화면에 티켓 번호·회차·선택 번호·마감시간을 표시한다.

`/내복권`은 보유/지난 티켓과 당첨·자동 입금 결과를, `/복권결과`는 회차별 당첨번호·등수별 당첨 장수·상금·이월액을, `/복권규칙`은 가격·확률·상금 배분을 보여준다. 관리자는 `$복권가격설정`으로 다음 회차 가격을 정하고, 마감·배분·구매한도는 DB 설정에서 관리한다. 판매 시작한 회차의 규칙을 소급 변경하지 않는다.

## DB와 추첨

모든 데이터는 `inazina.db`에 저장한다. `lottery_rounds`는 회차별 규칙 스냅샷·판매액·풀·당첨번호·추첨 상태를, `lottery_tickets`는 티켓별 구매자·번호·가격·결과를, `lottery_payouts`는 티켓별 상금·세금·입금 결과를, `lottery_pool_ledger`는 판매 배분·이월·상금 출금을 기록한다. 티켓에 회차/구매자/구매시간 인덱스를 두고 입금에는 `UNIQUE(ticket_id)`를 적용한다.

암호학적 난수로 회차 시작 시 비밀값을 만들고 SHA-256 해시를 사전 공개한다. 판매 종료 후 공개된 독립 난수와 결합해 중복 없는 7개 번호를 정한다. 추첨 뒤 비밀값·독립 난수·검증 방법을 공개한다. 외부 난수 공급자가 응답하지 않으면 추첨을 보류하며, 관리자가 유리한 난수를 재추첨하도록 허용하지 않는다. 외부 공급자를 도입하지 않는 1차 버전이라면 OS 난수와 사전 약속 해시만 사용하고 운영자가 비밀값을 알고 있다는 신뢰 한계를 명시한다.

회차 상태는 `selling → closed → drawn → settling → settled`로 이동한다. 서버 재시작 시 마지막 상태부터 계속하며 중복 추첨과 중복 입금을 거부한다. 마감 이후 구매는 DB에서 거부한다. 판매액, 각 풀 잔액, 상금, 세금, 국고 입금의 합계 검증이 실패하면 지급을 중단하고 운영자에게 원장 차이를 보여준다.

## 구현 시 검증할 항목

마감 직전 동시 구매, 잔액 부족, 중복 요청, 번호 중복/범위 초과, 재시작, 다수 당첨·동점, 무당첨 이월, 정수 반올림, 세금, 중복 입금, 국고와 풀 분리, 관리자 권한 취소, 회차 규칙 동결을 테스트한다. 당첨 결과와 추첨 검증 자료는 공개할 수 있지만 다른 사용자의 구매 내역은 본인과 관리자만 조회한다.

# LAPLACE 내부 위협모델

2026-11-21 기준. 내부 금융 시뮬레이터의 자산, 행위자, 신뢰 경계, 위협, 통제, 잔여 위험을 코드와 시험에 근거해 적는다. 증빙이 없으면 **미비**로 쓴다. 실제 규제 인증이나 외부 감사 결과가 아니다. 통제 번호는 `docs/controls_laplace.md`의 행이다.

## 자산
| 자산 | 위치 | 중요도 이유 |
|---|---|---|
| 원장(지갑·계좌·분개) | PostgreSQL `inazina` | 사용자 잔액과 회계 정합성의 근거 |
| 관리자 권한 | 웹 API 역할 `admin`, `BOOTSTRAP_ADMIN_IDS` | 쓰기 경로 전체를 연다 |
| 내부 토큰 | 환경변수 `INAZINA_INTERNAL_TOKEN` | 대시보드·API와 파이썬 서버 사이의 인증 |
| 비밀번호 해시 | `web_auth_credentials` | 로그인 |
| 감사 기록 | `admin_audit` | 관리자 행위의 사후 추적 |
| 백업 덤프 | pg_dump 파일 | 복구 수단이자 민감 데이터 사본 |

## 행위자와 신뢰 경계
| 행위자 | 신뢰 | 경계 |
|---|---|---|
| 일반 사용자 | 낮음 | 웹 API의 사용자 경로. 본인 자원만 |
| 국가·기업 계정 | 낮음~중간 | 역할 확인 후 자기 범위만 |
| 관리자 | 높음(내부자) | `/internal/admin/*`. 역할 확인과 감사 |
| 운영자(서버 접근) | 최고 | DB 직접 접근. 코드 통제 밖 |
| 외부 네트워크 | 없음 | 내부 토큰 없이는 `/internal/*`가 401 |

## 위협, 통제, 잔여 위험
| ID | 위협 | 통제 | 증빙 | 잔여 위험 |
|---|---|---|---|---|
| T-01 | 일반 사용자가 관리자 경로를 호출한다 | 모든 `/internal/admin/*` 분기가 관리자 역할을 확인한다(GET 33, POST 28). 새 경로가 확인 없이 추가되면 정적 검사가 실패한다 | C-30, tests/test_m8_admin_route_authorization.py | 역할 값 자체가 틀리면 막지 못한다. 관리자 목록은 1명(2026-11-21 접근 검토) |
| T-02 | 관리자가 흔적 없이 데이터를 바꾼다 | 관리자 쓰기는 감사 행·감사 범위·관리자 명령 계층을 거친다. 민감 조회(사용자 목록, 조달, ALM 등)는 `audit_admin_access`로 남는다 | C-10, C-30 | **해소(2026-11-24)**: login-history·audit 조회와 `/internal/admin/dr/monitor/sample` 쓰기가 감사 행을 남긴다(C-34). 관리자 쓰기의 이중 승인은 여전히 없다 |
| T-03 | 저장소에 비밀이 커밋된다 | `.env` 무시, 자격증명 패턴·하드코딩 리터럴 스캔 | C-31, tests/test_m8_secret_hygiene.py | git 이력 전체 스캔은 하지 않았다(`.env`가 이력에 없음만 확인). 패턴에 없는 형식의 비밀은 놓칠 수 있다 |
| T-04 | 오류 응답·로그로 비밀이 샌다 | 응답·로그 호출 인자에 비밀 변수명을 넣지 않는지 정적 검사. DB 편집기는 비밀 열을 가리고 감사 페이로드에도 값이 없다 | C-31, tests/test_pg_db_editor_secrets.py | **해소(2026-11-24)**: DB 오류는 일반 메시지와 요청 번호만 응답하고 상세는 서버 로그에 남는다(C-35). 검증용 `ValueError` 메시지는 의도된 업무 오류 코드라 그대로 나간다 |
| T-05 | 복구 훈련용 비밀번호가 프로세스 목록에 보인다 | pg_restore 비밀번호는 환경변수로 전달 | tests/test_m8_restore_cleanup_unit.py | 환경변수도 같은 계정의 다른 프로세스가 읽을 수 있다 |
| T-06 | 백업이 깨져서 복구를 못 한다 | 격리 DB 복원, 필수 표·외래키·통합 대사 점검, 임시 DB 정리 보고 | C-13, docs/m8_records/drills.json | 통합 대사 통과 기록 없음(2026-11-21 시도는 스키마 불일치로 실패). 백업 최신성은 화면에서 조회 전용으로 경고한다(C-37, 기준 48시간). `tools/backup_check.py`가 최근 백업이 기준 시간을 넘으면 종료 코드 1로 알리고 정기 점검 절차에 연결돼 있다(C-65). 스크립트(`tools/scheduled_backup.sh`)와 일정 절차·launchd 예시(`docs/m8_backup_schedule.md`)는 준비했지만 등록은 하지 않았다(사용자 결정). 일정이 등록되기 전까지 백업은 사람이 실행해야 한다(**미비**) 서비스 기동·전체 복구 시간은 측정하지 않았다 |
| T-07 | 시장 충격 뒤 장부가 어긋난다 | 통합 대사와 분개 대차 검사. 금리 급등, 예금 인출, 상관 부도, 담보 하락, 환율 급변, 결제 실패 6개 시나리오 | C-32, tests/test_m8_stress_scenarios.py | 소규모 시험 DB 기준이다. 운영 규모의 부하와 시간은 검증하지 않았다 |
| T-08 | 시험이 운영 DB를 건드린다 | 시험 중 기본 DB 디렉터리 격리 | C-14 | 운영 PostgreSQL DSN 자체의 격리는 환경 설정에 의존한다 |
| T-09 | 관리자 계정이 탈취된다 | 로그인 기록(로그인 서버가 남김). 4312/4313 의 별도 관리자 로그인 관문은 2026-11-22 삭제 | 일부(login-history) | 이상 접근 경보(로그인 실패 급증, 새 관리자 접속, 02~06시 KST 관리자 쓰기)를 감사·로그인 기록에서 읽기 전용으로 계산해 화면에 경고한다(C-65). 다중 인증은 SSO 쪽 범위라 이 저장소에서는 검증하지 않는다(현황만 기록: 이 저장소의 시험에 MFA 증빙 없음). **미비**: 관리자 세션 만료·재인증 시험. 부트스트랩 관리자 ID는 설정으로 바꿀 수 있다(C-36, 기본값은 기존 계정). 운영 환경에서 별도 값을 설정했는지는 확인하지 않았다 |
| T-10 | 관리자 권한이 오래 남는다 | 수기 접근 검토 1회(2026-11-21) | docs/m8_records/drills.json | 정기 검토 절차(docs/m8_access_review_procedure.md)와 기록 도구(tools/access_review.py), 35일 기한 경고가 있다(C-37). 관리자 권한 부여·회수는 추가 전용 기록(대상·이전/이후 권한·행위자·사유·승인자)을 남기고, 고위험 관리자 쓰기의 2인 승인(요청자≠승인자, 1회 사용, 만료, 추가 전용 승인 기록)을 옵트인으로 구현했다(C-39). **기본 꺼짐**이라 운영에서 켜기 전까지는 효과가 없고, 관리자가 2명 이상이어야 켤 수 있다. 사유는 켠 뒤에만 강제되고, 사용자 화면(계정관리)의 권한 변경 흐름에 사유 입력 칸이 있다(선택, 2인 승인이 켜져 있으면 필수). 복사본 DB에 붙인 실제 서버로 켜기→409→자기 승인 거부→다른 관리자 승인→재전송 성공→재사용 거부→끄기 승인까지 종단 확인했다(2026-11-28, C-67). 웹 화면, Discord 관리 명령(`admin_control.user` 공유 경로), 봇 시작 때의 부트스트랩 관리자 복원·최초 등록(행위자 `system:bootstrap`)이 모두 같은 기록에 남는다(C-66). DB를 직접 고치는 운영자 접근은 이 기록 밖이다(**미비**: 운영자 접근은 신뢰 경계 밖) |
| T-11 | 내부 토큰이 약하거나 비어 있다 | 서버는 토큰이 비면 모든 POST를 401로 거절하고 `hmac.compare_digest`로 비교한다 | tests/test_m8_secret_hygiene.py(환경변수 사용 확인) | 교체 절차(docs/m8_secret_rotation.md)와 점검 도구(tools/secret_rotation_check.py: 토큰 길이, 로그·파일의 자격증명 패턴, 마지막 교체 날짜)가 있고 화면이 교체 기한을 경고한다(C-65). **미비**: 교체 기록이 아직 없다(처음 교체 때 남긴다). 두 프로세스의 토큰이 일치하는지는 자동으로 확인하지 못한다 |

## 미비 요약(후속 작업 후보)
1. (해소 2026-11-24) 감사 기록 추가, DB 오류 일반화, 부트스트랩 관리자 설정화, 백업 최신성·접근 검토 기한 경고와 절차.
2. (구현 2026-11-27, 기본 꺼짐) 2인 승인, 권한 변경 기록, 교체 절차·점검 도구, 이상 접근 경보, 백업 점검 연결. 운영에서 2인 승인을 켜는 것과 처음 비밀 교체는 사용자 결정이다.
3. (구현 2026-11-28) 권한 변경 사유 입력 칸, 기존 쓰기 화면의 승인 필요 안내(공용 오류 처리), 봇·Discord 경로의 권한 변경 기록, 정기 백업 스크립트와 launchd 예시 문서(설치하지 않음).
4. 남은 미비: 2인 승인을 켜기 전까지의 효과 없음(켜는 것은 사용자 결정이고 관리자 2명 이상이 선행), 다중 인증(SSO 쪽), 관리자 세션 만료·재인증 시험, 백업 일정의 실제 등록(사용자 결정), 오프사이트·암호화 백업.

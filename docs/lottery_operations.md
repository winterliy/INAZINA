# Inazina 복권 운영

모든 금액은 게임 기준 통화이다. 복권 데이터는 `inazina.db`의 `lottery_rounds`, `lottery_tickets`, `lottery_purchases`, `lottery_payouts`, `lottery_pool_ledger`에 저장한다.

## 구매와 조회

```text
/복권구매 수량:1 번호:자동
/복권구매 수량:2 번호:1 2 3 4 5 6
/내복권
/내복권 회차:1
/복권결과
/복권결과 회차:1
/복권규칙
```

구매 화면의 **구매 확정** 버튼을 누르면 잔액을 차감하고 발권한다. 수동 번호는 1~45의 서로 다른 6개이고, 여러 장을 구매하면 각 장에 같은 번호를 사용한다. 자동 선택은 장마다 번호를 뽑는다. 구매 확인 후 회차가 바뀌었으면 기존 확인 창으로 다음 회차를 구매할 수 없다. 본인 티켓만 조회할 수 있고 티켓 번호·선택 번호·등수·상금·세금·자동 입금 결과를 페이지로 표시한다.

기본값은 한 장 1,000 기준 통화, 회차당 최대 100장, 토요일 20:00 한국시간 마감·20:05 추첨이다. 봇의 5초 정산 루프가 마감과 추첨 시각을 감지한다. 봇이 꺼져 있으면 다음 실행 시 마감된 회차부터 처리한다. 실제 지급 시각은 봇 실행 상태와 DB 대기에 따라 지연될 수 있다.

판매액은 상금 70%, 국고 20%, 준비금 10%로 배분한다. 상금 풀은 1~5등에 50/10/15/15/10%를 배분한다. 1등은 6개, 2등은 5개+보너스, 3등은 5개, 4등은 4개, 5등은 3개 일치이다. 등수별 당첨 장수로 나누고 미당첨 풀과 정수 나눗셈 잔액은 다음 회차로 이월한다. 준비금은 회차별 별도 원장에 보관하며 상금·국고와 혼용하지 않는다. 상금에 `settings.tax_percent`를 적용하여 세금은 국고에, 순상금은 당첨자의 지갑에 자동 입금한다. 상금은 적립된 풀 안에서만 지급한다.

## 관리자 설정

`$복권가격설정 [가격]`으로 가격을 변경한다. 나머지 구매한도·일정·배분은 DB의 `settings.lottery_config`를 편집한다. 변경은 다음 개설 회차부터 적용하고 판매 중인 회차 규칙은 동결한다.

```json
{"ticket_price":1000,"max_tickets":100,"prize_percent":70,"treasury_percent":20,"close_weekday":5,"close_hour":20,"close_minute":0,"draw_delay_seconds":300}
```

요일은 월요일 0~일요일 6, 시각은 한국시간이다. 상금·국고 배분 합계가 100%를 초과하면 거부한다. 나머지는 준비금이다. 관리자도 이미 발권된 회차의 번호·결과를 바꾸거나 재추첨하는 명령어는 제공하지 않는다.

## 추첨과 검증

회차 생성 시 32바이트 OS 난수 비밀값과 SHA-256 사전 약속을 저장하며 사전 약속은 구매 화면에 공개한다. 마감 후 추첨 시 별도의 OS 난수를 저장한다. 두 값을 결합한 SHA-256 카운터 스트림에서 편향 없는 거절 샘플링으로 본번호 6개와 보너스 1개를 정한다. `/복권결과`에 비밀값·추첨 난수·사전 약속을 공개한다.

검증은 `hashlib.sha256(bytes.fromhex(secret)).hexdigest() == commitment`와 `LotteryManager.draw_numbers(secret, entropy)`로 가능하다. 외부 독립 난수 공급자는 사용하지 않으므로 운영자가 서버·DB·비밀값을 관리한다는 신뢰 한계는 남는다.

추첨 결과를 먼저 확정 저장하고 지급은 별도 원자적 트랜잭션에서 처리한다. 지급 오류가 발생해도 번호를 다시 뽑지 않는다. 구매 요청 ID와 티켓별 지급 기본키로 중복 차감·발권·입금을 막는다. 판매 배분과 등수별 풀 원장을 검증하여 불일치하면 지급을 보류한다. 계정 삭제나 잔액 상한으로 지급이 불가능한 경우 원인을 해결한 뒤 같은 확정 결과로 재개한다. 복권 기록은 일별 그래프 로그 정리에서 삭제하지 않는다.

관리자는 `$복권당첨번호보기`와 `$복권당첨번호변경 [번호 6개] [보너스(선택)]`을 사용할 수 있다. 지정 번호는 추첨 전 일반 사용자에게 노출하지 않으며 추첨 후 결과에 관리자 지정 회차라고 표시한다. 지정 회차는 OS 난수로 번호를 재현하는 검증을 적용하지 않는다. 정산 완료 회차는 변경하지 않는다.

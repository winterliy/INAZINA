# 대외용 메일 기획안 (개인용 기업 이메일)

작성: 2026-11-28 · 상태: 초안(결정 필요 항목 있음)

## 1. 목적과 범위

- 목적: 외부 사람과 주고받는 `이름@회사도메인` 형태의 기업 이메일을 개인용으로 만든다.
- 불특정 다수에게 열지 않는다. 사서함은 본인(필요하면 소수의 지정 인원)만 쓴다. 회원가입·자동 발급 없음.
- 내부 메일(work 앱의 쪽지)과는 별개다. 내부 메일은 `*.inazina.localhost` 안에서만 돌고, 대외 메일은 인터넷 메일 표준(SMTP/IMAP)을 쓴다.

## 2. 먼저 정해야 할 충돌: 도메인

기존 결정(2026-11-22)은 "`*.inazina.localhost`만 쓰고 공개 DNS·공개 인증서 없음, `.kr` 폐기"였다.
대외 메일은 **인터넷에서 풀리는 실제 도메인이 반드시 필요**하다(MX 레코드가 있어야 외부에서 메일이 들어온다).
따라서 다음 중 하나를 고른다.

- (가) 메일 전용으로 공개 도메인 1개를 새로 구입한다. 웹 서비스는 계속 `.localhost`로 둔다. **권장**: 기존 결정을 건드리지 않고 메일만 외부와 연결된다.
- (나) 대외 메일을 하지 않는다.

## 3. 구축 방식 비교

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 호스팅형 (권장) | Google Workspace, Microsoft 365, NAVER WORKS, Zoho, Fastmail 등에 자기 도메인을 연결 | 도달률(스팸함 안 가는 것)이 좋음, 유지보수·보안 패치·백업을 맡김, 웹/모바일 앱 제공 | 월 비용, 메일이 외부 사업자 서버에 저장됨 |
| B. 직접 운영 | Mailcow, Postfix+Dovecot 등을 서버에 설치 | 데이터 완전 통제, 비용은 서버값뿐 | 집 IP는 대개 25번 포트가 막혀 있고 스팸 판정을 받기 쉬움. 24시간 켜진 고정 IP 서버, 역방향 DNS, 평판 관리, 보안 패치가 필요 |
| C. 하이브리드 | 수신은 도메인 전달(포워딩) 서비스, 발신은 SMTP 릴레이(SES, Mailgun 등) | 저렴, 사서함 관리 불필요 | 설정이 복잡하고 사서함 기능이 약함 |

이 Mac 한 대에서 쓰는 구조라서, 직접 운영(B)은 24시간 가동과 도달률 문제 때문에 권하지 않는다.

## 4. 권장안

**호스팅형(A) + 자기 도메인.** 사서함 1~3개(예: 본인, 대표 주소, 문의용 별칭)만 만든다.

1. 도메인 구입(등록기관의 2단계 인증, 자동 갱신, WHOIS 개인정보 가리기 켜기)
2. 메일 사업자 가입 후 도메인 소유 확인
3. DNS 설정
   - MX: 사업자 안내대로
   - SPF: 발신 허용 서버 선언
   - DKIM: 사업자가 주는 서명 키 등록
   - DMARC: 처음엔 `p=none`으로 보고서만 받고, 이상이 없으면 `quarantine` → `reject`로 단계적 강화
   - (선택) MTA-STS, TLS-RPT
4. 사서함·별칭 생성(`me@`, `contact@`, `admin@`, `postmaster@`, `abuse@`)
5. 보안
   - 모든 사서함 2단계 인증(보안키 또는 앱 방식), 비밀번호 관리자 사용
   - 가입 비공개: 관리자만 사서함 생성
   - 포워딩 규칙 외부 전송 제한, 관리자 로그인 알림
6. 시험: 외부 계정(Gmail 등)으로 송수신, 스팸 점수 검사 도구로 SPF/DKIM/DMARC 통과 확인

## 5. work 앱과의 관계

- 1단계(기본): 연동하지 않는다. 대외 메일은 사업자의 웹/모바일 앱으로 쓴다. 보안상 가장 단순하다.
- 2단계(선택): work 홈에 "대외 메일 열기" 링크와 안 읽은 개수만 표시한다(사업자 API 사용, 비밀번호는 저장하지 않고 OAuth만).
- 하지 않을 것: work MySQL에 외부 메일 본문 저장, 무제한 자동 발송, 외부 수신자에게 내부 시스템 정보 노출.
- 공지·결재 알림을 대외로 내보내는 기능은 도메인이 생긴 뒤 별도로 정한다.

## 6. 운영·법적 유의

- 개인용이라도 외부에 발송하는 주소는 신원이 드러나므로, 도메인 등록 정보와 서명(이름·직함·연락처)을 한 번 점검한다.
- 개인정보(상대방 메일 주소 등)를 다루므로 개인정보처리방침의 "수집 항목"과 충돌하지 않는지 확인한다. 공식 사이트 약관과는 별개 서비스로 둔다.
- 백업: 사업자 보관에 맡기되 중요한 메일은 주기적으로 내려받기(IMAP 백업)를 둔다.
- 퇴사/폐쇄 절차: 도메인 갱신 담당, 사서함 삭제·전달 설정 절차를 문서화한다.

## 7. 비용 감각 (대략, 변동 있음)

- 도메인: 연 1~3만 원 수준(.com 기준)
- 호스팅형 메일: 사서함당 월 수천 원~1만 원대 (사업자·요금제별 확인 필요)
- 직접 운영(B): 서버 월 수천~수만 원 + 관리 시간

## 8. 결정 필요 항목

1. 공개 도메인을 새로 살 것인가 (가: 예 / 나: 대외 메일 안 함)
2. 메일 사업자 후보 (Google Workspace, Microsoft 365, NAVER WORKS, Zoho, Fastmail 등)
3. 만들 사서함 수와 이름 규칙
4. work 앱과 1단계만(연동 없음) 갈지, 2단계까지 갈지

## 9. 일정(안)

| 단계 | 내용 |
|---|---|
| 0 | 도메인·사업자 결정 |
| 1 | 도메인 구입, DNS(MX/SPF/DKIM/DMARC) 설정, 사서함 생성 |
| 2 | 보안 설정과 송수신 시험 |
| 3 | DMARC 단계적 강화(2~4주 관찰) |
| 4 | (선택) work 홈에 링크·안 읽은 개수 표시 |

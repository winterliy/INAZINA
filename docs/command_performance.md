# 명령어 조회·차트 최적화

## 2026-10-09 추가 적용

- 전체 종목 목록은 종목마다 조회하는 대신 한 읽기 스냅샷에서 9개 SQL로 구성한다.
  전역 코드 중복 검사, 만기 상태, 옵션 이론가·최근 체결가·사건 가격 우선순위를 유지한다.
- 환율은 통화와 연결 자산을 JOIN한 요청별 스냅샷으로 평가한다. Fraction/Decimal과
  통화별 소수 자릿수·절삭·한도 검증을 유지한다. 지갑의 외환통장·현금에도 같은 스냅샷을 쓴다.
  다음 요청에서는 다시 조회하므로 DB Browser 변경이 반영된다. 거래·정산에는 적용하지 않는다.
- 검색의 환율·금리·지수·저축·대출 페이지는 불필요한 전체 종목 조회를 생략한다.
- 지갑 텍스트 준비를 작업 스레드로 옮겼다. 우선주 여부도 보유자산 일괄 조회에 포함하여
  Discord 이벤트 루프에서 종목별 회사 조회를 하지 않는다. 사용하지 않는 상세 임베드 생성도
  제거하여 메인 요약에 보유 내역이 섞이던 얕은 복사 문제를 해결했다.
- 주식·상품·거래소 지수 그래프는 기존 코드/시각 인덱스로 SQL OHLC를 집계한다.
  화면 경계 안 첫 가격과 원본 기록 수를 함께 읽고, 현재가를 마지막 봉에 반영한다.
  지표 준비 기간, 거래량, 매물대용 원본 체결, VWAP, ELS 기준선은 유지한다.
  PNG 캐시 키에 OHLC도 포함하여 고가·저가만 바뀌어도 새로 그린다.
- `inazina.performance` INFO 로그에 100ms 이상인 `wallet.snapshot`, `wallet.format`,
  `market.listings`, `chart.query`, `chart.draw` 단계만 기록한다. 사용자 ID·잔액·인자는 기록하지 않는다.
  이 로그는 서버 내부 준비 시간이며 Discord API 왕복 시간은 포함하지 않는다.

임시 DB에서 각 7회 중앙값을 비교했다. 종목 100개(각 2주 보유), 추가 통화 50개이며,
지갑은 정산을 제외한 평가만 측정했다. 차트는 초당 기록 86,400개를 10분봉으로 집계했다.
실제 사용자 DB에 테스트 데이터를 넣거나 봇을 재시작하지 않았다.

| 대상 | 변경 전 | 변경 후 |
|---|---:|---:|
| 전체 종목 조회 | 5.140ms | 1.715ms |
| 지갑 평가 | 2.865ms | 2.522ms |
| 환율 목록 | 2.058ms | 1.460ms |
| 차트 가격 조회·캔들 집계 | 68.724ms | 31.487ms |

마지막 행은 원시 기록 조회+Python 집계와 SQL 집계를 비교한 값이며 PNG 생성 시간은 제외한다.
모든 수치는 로컬 실험으로 실제 Discord 명령어 응답 개선율을 뜻하지 않는다.
DB 스키마·운영 데이터·CPython 기본 실행은 유지한다. 요청 간 가격 캐시나 JIT는 추가하지 않았다.

관련 검사에서는 읽기 중 쓰기 잠금 비점유, 새 요청의 가격 갱신, 종목 조회 결과 일치,
통화 환산 정밀도, 일반/지수 OHLC·PNG 일치, 화면 중간 경계의 변동 기준가와 기록 수,
현재가의 기존/신규 봉 반영, 고가 변경 시 캐시 무효화, 지갑 메인 분리를 확인한다.
기존 NWX 환율 검사에서 USD 국적 사용자를 쓰던 데이터는 NWX 국적 사용자로 바로잡았다.

## 2026-10-06 적용 기록

지갑은 이자·외환 이자·만기 정산을 먼저 완료한 뒤, 별도의 읽기 전용 연결에서
하나의 WAL 스냅샷으로 평가한다. 화폐 표시·국채 보유·ELS 상세도 조회 시
쓰기 잠금을 예약하지 않는다. 기존 일반 DB 연결과 SELECT 잠금,
거래·송금·정산의 파일 잠금/BEGIN IMMEDIATE/트랜잭션 내부 권한 검사는 유지한다.

보유 종목·옵션 기초자산은 일괄 읽고, 통장·선물 상품은 JOIN한다.
코드 중복 시 기존처럼 평가 제외/확인 필요로 표시한다. 읽기용 데이터는 조회 한 번 동안만
재사용하고 다음 조회에서는 DB Browser 편집을 다시 읽는다. 구형 SQL 스키마명 변환만
최대 512개 문자열을 재사용한다. 대체 후 호출자가 없는 기존 종목 조회 함수는 제거했다.

금액 변환이 필요 없는 지갑·검색·그래프 등은 공통 준비 과정에서 MoneyDisplay를 만들지
않고, 필요한 MoneyDisplay와 검색 임베드 생성은 작업 스레드에서 수행한다.
검색은 개인 이자를 정산하지 않고 메인은 카테고리별 개수만 구한다.
이자는 사용자/상품 대상이 있을 때 직접 WHERE 조건을 구성하고 상품 정보를 일괄 읽는다.

차트는 선택 지표의 공통 계산만 수행한다. SMA는 이동 합계를 사용하고 표준편차·CCI 편차는
창의 평균을 한 번만 구한다. 사각형은 행 단위로 채운다. 최대 16개 PNG를 가격 기록·거래·
봉 주기·표시 종료 시각·지표·VWAP 앵커·ELS 기준선이 모두 같은 경우 재사용한다.
종료 시각이 지정되지 않은 호출은 캐시하지 않는다. 캐시는 금액/거래 권한 판단에 쓰지 않는다.

## 측정

임시 DB의 종목 50개, 종목별 10주 지갑 조회 30회 중앙값이다. Discord API 왕복은 제외했다.
기존 지갑 평가 및 목록과 결과가 같았다. 360개 봉의 37개 지표는 기존 계산과 오차 범위 내
같았고 대표 차트 PNG 바이트도 같았다. 전체 봇이나 실제 Discord 응답시간의 측정은 아니다.

| 대상 | 이전 | 이후 |
|---|---:|---:|
| 지갑 조회 | 8.137ms | 2.238ms |
| 지갑 SELECT | 536회 | 36회 |
| 기본 SMA·거래량 지표 계산 | 3.722ms | 0.156ms |
| 볼린저·슈퍼트렌드·RSI·CCI·MACD 계산 | 4.701ms | 2.031ms |
| 동일 차트 PNG 재사용 | 첫 생성 21.181ms | 재사용 0.014ms |

원본 적용 후 관련 검사 41개를 통과했다. 동시 지갑 읽기에서 미커밋 잔액 비노출,
읽기 연결 쓰기 거부, 동시 송금 초과 지출 방지, 롤백·권한 취소,
화폐 평가·연장이율·검색·ELS 표시·지표·정산을 검증했다.
화폐 일반화 이전 NWX 고정 및 모든 외환통장을 외환 카테고리로 가정한 기존 검사 2개는
원본 변경 전에도 실패함을 확인했으며 이번 변경에서 해당 검사 기대값은 수정하지 않았다.

## 적용 범위

자동 승인 검토에서 일반 SELECT 연결 교체를 포함한 광범위한 패치가 거절되어,
기존 연결과 잠금을 유지하는 지갑 전용 읽기 경로로 범위를 줄여 적용했다.
시장 시뮬레이션·시장 전체 종목 조회 구현·봇 사용자 준비 로직·기존 테스트는 유지했다.

## 운영 DB 빈 공간 정리

봇 프로세스가 실행 중이지 않음을 확인한 후 SQLite 백업과 VACUUM을 수행했다.
운영 inazina.db는 590.8MiB에서 28.9MiB로 줄었다. 모든 일반 테이블의 행 수와 전체 값
해시가 전후 같았고 integrity_check도 통과했다. 이 수치는 파일 용량 감소이며 명령어 속도
증가율을 의미하지 않는다. 백업: `/private/tmp/inazina-opt/inazina_before_vacuum.db`.

# LAPLACE 금융 시뮬레이터 현실화 계획

## 목표와 범위

내부에서만 동작하는 현실성 높은 금융 시뮬레이터를 만든다. 기존 데이터와 기능을 우선 재사용한다. 실제 은행·수탁기관·세무기관 연결, 실제 KYC 자료 수집, 외부 인증 취득은 범위 밖이다. 기준금리 결정권은 관리자에게 둔다.

## M4 — #74 상품화폐 회계 완료 기준

- [x] 금액 필드 등록부, 행 단위 최소단위 snapshot, 미분류 스키마 감사 및 관리자 통합 대사 연결. 이 검사는 소비자 코드 전체 계보를 증명하지 않는다.
- [x] 지원하는 모든 상품 거래의 통화 최소단위/Decimal 경계를 적용한다. 일반·외화·직접·소수점 현물 거래와 손익/세금 원가, 옵션(기준통화 0자리 전용), 선물 증거금·손익(기준통화 상품), 회사채 쿠폰, 국채 1차/2차 매수·보유원가·이전, 대출 원금·상환·수수료·담보·ECL을 통화별 canonical 최소단위로 계산한다. 보유자산 가중원가는 `AssetCostManager`에서 통화별 정수 최소단위로 관리한다. 0자리 기준통화로 제한한 상품은 그 제한을 검증하고, 소수 통화 상품은 통화 설정의 scale을 사용한다. REAL 열은 호환 미러/표시 경계에만 남는다.
- [ ] 고객·기관·회사·세금·시장·펀드·대출·채권 간 원금·현금·수수료·세금·손익을 실제 업무 전기와 연결한다. 시장/기관 clearing, FX clearing, 일부 법인·펀드·세금 경로가 남았다.
- [ ] 모든 보조원장을 계정 매핑과 함께 공통 전기에 연결하고 통화·정밀도별 시산표를 대사한다. 현재 통합 보고서는 구현된 검사만 집계한다.
- [ ] 기존 잔액은 근거가 있는 범위에서 재구성하고, 불가능한 과거는 명시 baseline으로 분리한다. 업무별 rollback·재실행 멱등성·마감·정정 통합검증이 남았다.
- [ ] 전체 금액 계보·보조원장 대사·스트레스 및 close 게이트를 실행하고 제한을 문서화한다.

통합 금융원장 보고서는 SQLite에 선언된 외래키 위반을 검사하고 관리자 웹 화면에 오류 수와 상세를 표시한다. 선언되지 않은 업무 참조의 전체 검증까지 보장하지는 않는다.

선언된 외래키가 없는 대출 상환표의 대출 참조도 통합 대사에서 별도 검사한다.

고객 지갑 대사는 기존 고객·계좌에 연결되지 않은 0이 아닌 잔액을 보고한다. 계좌 해지와 국적 변경은 계좌 삭제 전에 지갑 출금을 전기한다. 과거 해지 계좌는 지갑 이력과 은행·공통 해지 분개의 금액·통화·시각이 일치하면 관리자 웹에서 현재 기간에 조정할 수 있다. 근거가 불충분한 과거 잔액은 추정하지 않으며, 조정 근거와 중복 실행·부분 실패도 검사한다.

대손상각·ECL·담보·보증·미인출 약정과 관련 이력도 존재하지 않는 대출을 가리키는지 검사한다.

M4 Step 2의 금액 계산 경계는 완료했다. 옵션·선물·일부 펀드가 기준통화에 제한된 것은 현재 상품 규칙이며, 기준통화는 소수점 0자리다. 소수 통화 상품은 통화 설정에서 scale을 읽는다. 옵션 프리미엄 체결·매수 예치/환불·수취 지갑 또는 펀드·공통 분개를 연결했다. 기존 체결은 수량 baseline으로 보존한다. 옵션 행사 대가·담보와 나머지 상품의 기관·고객·발행자 공통 전기 및 보조원장 대사는 Step 3 이후의 미완료 범위다. 따라서 Step 2 완료가 M4 전체 완료를 뜻하지는 않는다.

2026-10-30 후속에서는 `AssetCostManager`와 상품 통화별 계산 경계를 마무리했다. 보유원가, 소수 통화 지정가와 체결, 국채 원금·매입·2차 이전까지 canonical 최소단위를 사용한다. 공통 전기·수취 지갑 연결·보조원장 대사·과거 재구성·마감 검증은 별도 M4 항목으로 열린 상태다.

M4 Step 3 진행: 신규 환전·송금은 출금과 입금을 각각 해당 통화 최소단위로 전기하고, 분할 출금까지 실제 지갑 행과 연결한다. 국고 수수료는 부과 통화와 실제 수취 통화를 모두 보존하고, 환산 후 0으로 반올림된 경우도 구분한다. 옵션 프리미엄 및 환전·송금 대사는 관리자 원장 보고서와 사용자 지갑 명세에 반영한다. 과거 거래의 지갑 링크 복원과 금융기관 간 정산 연결은 남아 있다.

세금과 같은 통화로 수취한 국고 지갑의 정밀도도 세금 원장과 대조한다. 서로 다른 통화의 수취와 환전 전기 간 완전한 금액 대사는 아직 남아 있다.

신규 예금이자 세금은 금융기관 송금 분개를 세금 거래와 연결한다. 외화 세금의 원천통화 세액과 국고 수취통화 양쪽 분개, 실제 지갑 입금, 거래 시 환율 스냅샷을 대조한다. 도입 전 이자는 기준점으로 보존하며, 다른 세금 경로의 환율 기록 및 대사는 아직 미완료다.

예금이자 세금의 국고 입금은 국가 통화의 최소단위로 처리해 소수 통화 세액을 보존한다.

환전 후 세금이 수취 통화 최소단위 미만이면 원천통화 분개와 환율을 보존하고, 0원 지갑·목적통화 분개를 만들지 않는다. 원천통화 FX clearing에 남는 반올림 잔여의 장기 정리 정책은 미완료다.

금융기관 분개 재실행 시 동일 키가 다른 통화·정밀도·분개 금액을 가리키면 거부한다. 같은 분개의 재실행은 기존처럼 중복 전기하지 않는다.

금융기관 분개의 공통 계정 매핑은 묶어서 등록해 분개당 반복 스키마 초기화 호출을 줄인다.

회사·금융기관 보조원장 대사는 공통 분개의 주체 유형까지 식별키에 포함해 서로 다른 주체의 분개를 잘못 일치시키지 않는다.

기관 분개와 공통 분개, 외화 세금 송금의 양쪽 통화 분개는 각각 저장점으로 묶어 내부 실패를 호출자가 잡아도 부분 전기가 남지 않게 한다.

세금 송금과 환율 연결 기록을 생성하는 중 실패하면 두 기록을 함께 롤백한다.

외부 DB 트랜잭션에서 이자 정산이 실패해도 계좌 잔액·국고 입금·금융기관 분개를 모두 되돌리도록 정산 단위 저장점을 적용한다.

세금 송금과 환율 이관 기준점은 재시작에서 유지하며, SQL REPLACE를 통한 변경도 차단한다.

새 세금 송금 링크와 환율 스냅샷도 SQL REPLACE를 차단하고 하나의 은행 분개를 여러 거래나 양쪽 송금 단계에 중복 연결하지 못하게 한다.

마감 보강: 공통원장 마감 구간에 직접 SQL이나 자동 전기로 분개와 분개선을 추가하지 못하도록 DB에서 차단한다. 재시작 시 기존 지갑 행의 중복 기초 잔액 생성을 막고, 마감 스냅샷의 분개 수와 해시를 통합 대사에 포함한다. 전체 보조원장 마감 게이트와 과거 잔액 재구성은 아직 미완료다.

공통원장 기간 마감은 해당 통화의 분개에 서로 다른 최소단위 정밀도가 섞여 있으면 거부한다. 이 검사는 전체 보조원장 마감 게이트를 대체하지 않는다.

기간 마감 행을 직접 입력하는 경우에도 불완전하거나 불균형인 공통 분개를 DB에서 거부한다. 스냅샷의 정확성과 보조원장 정합성은 별도 대사로 확인해야 한다.

이미 저장된 마감 스냅샷은 SQL REPLACE로 덮어쓸 수 없으며, 같은 정상 마감 요청의 재실행은 기존 마감 ID를 반환한다.

신규 마감 해시에는 분개 주체 유형·통화 정밀도·기록 시각·설명과 분개선 식별자도 포함한다. 이전 해시는 기존 방식으로 검증하며 과거의 포함되지 않은 속성을 사후에 증명하지는 않는다.

공통 분개 역시 SQL REPLACE에 의한 덮어쓰기를 차단한다. 은행정리 관리자 보고서 회귀는 추가된 옵션·환전·기간마감 대사 범위를 확인한다.

공통 분개선도 기존 행 ID를 SQL REPLACE로 덮어쓸 수 없게 보호한다.

옵션 행사 시 신규 콜·풋 행사가액과 세액을 불변 이벤트 및 공통 분개로 기록하고 계약·분개를 대사한다. 신규 콜 행사 출금 및 콜·풋 행사 수취를 실제 고객 지갑 또는 펀드 현금 행과 연결한다. 과거 행사 지갑 연결은 명시적 baseline으로 남으며 풋 현금담보와 주식 이동의 직접 연결은 미완료다.

신규 옵션 행사의 담보와 기초주식은 같은 트랜잭션에서 행사 전후 잔량과 이동량을 불변 기록으로 남기고 대사한다. 과거 행사는 별도 baseline이며, 이 수량 스냅샷은 전체 담보 생애주기의 개별 원장 연결이나 과거 거래 재생을 대체하지 않는다.

현재 옵션 담보는 미체결 작성 수량과 발행 잔량을 기준으로 주식·현금 담보 및 보유 포지션을 대사한다. 과거 담보 설정·반환의 개별 지갑 연결과 재구성은 남아 있다.

신규 풋 현금담보의 설정·반환은 실제 고객 지갑 변동 및 공통 분개에 연결하고, 설정·반환·행사 합계와 현재 담보 잔액을 대사한다. 적용 전 계약은 기준점으로 분리하며 과거 지갑 내역을 추정하지 않는다.

풋 현금담보 대사는 이벤트의 소수 자릿수를 확인하고 분개선을 한 번에 조회한다. 이 개선은 전체 거래·보조원장 대사 완료를 의미하지 않는다.

옵션 행사 현금·자산 연결의 과거 baseline은 초기 이관 때만 기록하며, 활성화 이후 새 예외를 추가하지 못한다. 기존 baseline의 진위 검증 및 다른 거래의 과거 이관은 별도 과제로 남는다.

옵션 행사 대사의 현금 연결은 행사별 반복 조회 대신 일괄 조회한다. 행사 분개·자산 이동의 다른 대사와 전체 통합 검증은 별도로 유지한다.

옵션 담보 대사는 고아 포지션·발행 주문, 발행자 불일치, 비활성 계약의 열린 발행 주문도 보고한다. 이는 전체 보조원장 대사 완료를 뜻하지 않는다.

## 후속 단계

### M6 — 조달·금리·Basel·ALM

1. 은행채·은행간·RP·중앙은행 조달과 만기/담보/가격/한도를 원장화한다.
2. FTP와 예금 행동만기·금리베타를 상품 가격에 연결하고 시장·기대 입력으로 곡선/선도금리를 만든다.
3. CET1/AT1/Tier 2, 완충자본, 관할별 RWA·레버리지, HQLA·LCR·NSFR를 구현한다.
4. 담보·유동성·행동만기를 반영한 ΔNII/ΔEVE와 경계 테스트를 추가한다.

### M7 — 계약·법률·회수·시장·FX

1. 혼합/단계 금리, fixing·고지·부분상환·한도대출을 보강한다.
2. 준거법·고객/상품 유형·관할·계약일별 최고금리, APR, 세금 규칙을 구성한다.
3. 연체 waterfall, 채무조정·파산·회수곡선·NPL과 채권자 우선순위를 연결한다.
4. 예금보험기금/정리, 채권 위험지표·파생/헤지, 통화별 ALM·환위험을 검증한다.

### M8 — 보안·준법·완료 검증

1. 내부 위협모델, 최소권한, 비밀관리, 접근/변경 감사, 백업·복구와 보존정책을 검토한다.
2. KYC·AML은 내부 정책·사례관리로 한정하고 실명자료나 외부 제재목록 연동은 두지 않는다.
3. 규제 통제-증빙표와 사고/복구 훈련 기록을 준비한다. 실제 인증 취득은 완료조건이 아니다.
4. 금리급등·예금인출·상관부도·담보하락·환율급변·결제실패 복합 스트레스에서 회계 불변식을 검증한다.
5. 금액 정밀도, 전 원장 대사, 국가별 법률/APR/세금, 권한·불변 이력의 전체 통합 게이트를 통과시킨다.

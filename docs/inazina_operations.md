# Inazina 운영 안내

운영 DB는 `database/inazina.db` 하나다. 통합된 기존 `users.db`, `accounts.db`, `assets.db`, `product.db`, `company.db`, `pot.db`, `tax.db`, `system.db`는 무결성·이전 기록 검증 및 복구 ZIP 생성 후 정리한다. 이전 기록도 ZIP에 보존하며 별도의 기록 전용 DB는 정리 대상에서 제외한다. DB Browser는 **inazina.db**를 열어야 한다. 파일명과 작업 폴더명은 별개이므로 기존 프로젝트 폴더를 옮길 필요는 없다.

## 관리자 명령어

DB `users.role=admin`만 `$` 명령어에 응답한다. 일반 사용자의 입력은 메시지 전송·삭제 없이 무반응이다. 관리자는 서버 채널에 입력한 명령의 결과를 개인 DM으로 받은 뒤 원래 채팅을 삭제한다. DM에서 직접 입력한 `$` 명령은 삭제하지 않는다. DM에서 인증 코드나 추가 확인 문구를 입력할 필요는 없다. 명령어·버튼은 실행자에게만 연결되고 저장 시 관리 권한이 유지되는지 확인한다. 봇의 Message Content Intent와 서버 메시지 관리 권한, 관리자의 DM 허용이 필요하다. DM을 전달할 수 없으면 작업을 실행하지 않는다.

일반 사용자 `/도움말`은 별도 텍스트 없이 외부 도움말 링크 버튼만 표시한다. `$도움말`과 `$help`는 관리자 명령어와 국가 명의 기능을 함께 안내한다. 기존 `$stock`, `$asset`, `$etf`, `$future`, `$corporatebond`, `$fund`, `$indexfund`, `$commodity`, `$bond`, `$saving`, `$loan`, `$option`, `$currency`, `$currencyproduct`, `$catalog`, `$국고`, `$user`, `$volatility`, `$settings`, `$setup`, `$register`와 이전 별칭은 더 이상 등록하지 않는다.

| 명령어 | 인자·용도 |
|---|---|
| `$상품수정` | `[id] [상품종류] [유형별 순서형 인자 ...] [추가 JSON(선택)]` · 상품 설정 전체 수정 |
| `$상품가격수정` | `[종목id] [add/del/modify] [금액]` · 가격 더하기/빼기/지정값 |
| `$상품생성` | `[id] [상품종류] [유형별 순서형 인자 ...] [추가 JSON(선택)]` |
| `$상품삭제` | `[id]` · 기록을 보존하고 거래 중지; 미체결 주문·계약 의무는 먼저 정리 |
| `$정기배당수정` | `[id] [주기] [주당 배당금 또는 비율%]` · 고정금액/가격 기준 비율 중 하나로 정규배당 설정 |
| `$정기배당활성` | `[id] [on/off]` · 주기·금액을 유지하며 정규배당 켜기/끄기 |
| `$법인잔고수정` | `[보통주회사id] [add/del/modify] [금액]` · 자본금과 별도인 법인 현금 계정 조정 |
| `$법인청산` | `[보통주회사id]` · 채무·확정 배당·우선주·보통주 순으로 법인 현금 배분 |
| `$ELS취소` | `[id]` · 모집 중 ELS 청약금·쿠폰 예치금 환불 |
| `$특별배당실시` | `[id] [주당 배당금]` · 정규배당 활성 상태와 별도로 일회 지급 |
| `$기본소득` | `[국가] [금액]` · 그 국가 국고에서 그 국가 시민에게 국가 화폐로 지급 |
| `$사건` | 인자 없이 실행 → DM 버튼 → 상품코드·호악재·duration·변동률·선택 목표금액 모달 |
| `$잔고수정` | `[user_id/계좌번호] [add/del/modify] [금액]` · 사용자 지갑 또는 일반/외환통장 잔고 |
| `$등록` | `[user_id]` · 시민 등록 |
| `$도박확률` | `[0~100]` |
| `$도박리턴값` | `[리턴 퍼센트]` |
| `$시장분위기` | `[bull/flat/bear]` |
| `$상품분위기` | `[종목id] [bull/flat/bear]` · 자동 가격 종목의 개별 흐름 |
| `$복권당첨번호보기` | 현재 지정 번호 또는 직전 추첨 번호를 관리자에게 표시; 자동 번호는 추첨 시 결정 |
| `$복권당첨번호변경` | `[번호 6개] [보너스(선택)]` · 현재 미추첨 회차 지정. 보너스를 생략하면 남은 번호에서 무작위 선택 |
| `$세율` | `[퍼센트]` |
| `$소득세율` | `[국적] [소득원 코드] [퍼센트\|기본]` · 국가 기본세율보다 우선하는 소득원별 세율. 예: `낙원 lottery_winnings 12`; `기본`은 예외 규칙을 지워 국가 세율로 복귀 |
| `$환율수정` | `[외화A] [외화B] [비율]` · 1 A = 비율 B. B 시세 유지, A 시세를 정수 기준 통화로 반올림 |
| `$복권가격설정` | `[가격]` · 다음 개설 회차부터 적용 |
| `$금리수정` | `[국적] [add/del/modify] [수치]` · 국가별 기준금리, 연 퍼센트 |
| `$시장금리수정` | `[국적] [funding/bank_bond/treasury] [만기일수] [금리%]` · 만기별 시장 기준지표 |
| `$법정최고이자수정` | `[국적] [add/del/modify] [수치]` · 국적별 상품 연이율 상한 |

```text
$상품생성 NEW company "새 주식" 게임 100000000 100000 1000 INZ
$상품가격수정 NEW add 100
$상품삭제 NEW
$잔고수정 123456789 modify 1000000
$환율수정 USD EUR 0.9
$금리수정 낙원 modify 3
$법정최고이자수정 낙원 modify 20
```

생성 유형은 `company`(주식, `stock` 별칭도 지원), `preferred`(우선주), `asset`(시장 자산), `dr`(주식예탁증서), `etf`, `els`, `future`(주식 선물), `corporatebond`(회사채), `fund`(일반 펀드), `indexfund`, `commodity`(현물 원자재), `bond`(국채), `saving`(저축), `loan`(대출), `option`, `currency`(통화), `currencyproduct`(외환통장)다. 한글 유형도 지원한다. 두 번째 인자인 상품종류에 따라 이후 인자의 이름과 순서가 달라진다. 공백이 있는 이름·문자열은 따옴표로 묶는다. 마지막 추가 JSON은 선택 사항이며 `quote_currency`, `is_fixed`, `dividend_is_active` 등 기본 인자 외 설정을 지정할 때만 사용한다. 이미 입력한 기본 인자를 JSON에서 중복 지정할 수 없다. 이전 key=value·전체 JSON 입력은 호환용으로만 유지한다.

```text
$상품생성 SAV saving "새 적금" 3 1000 30 86400 1 Inazina
$상품생성 USDACC currencyproduct "달러통장" USD 1
$상품생성 CALL1 option INZST001 call 1500 30 1 100 50
$상품생성 KOCO_DR_LN dr "KOCO DR" 25 10000 LSE {"underlying_code":"KOCO","underlying_per_receipt":2,"quote_currency":"ABC","depositary_bank":"Example Depositary","custodian":"Example Custody","home_exchange_id":"KRX"}
```

옵션 생성은 국가의 담보가 필요하다. 기존 상품의 결제 통화와 발행된 파생·채권 계약 조건은 변경하지 않는다. 가격 없는 저축·대출 상품에 `$상품수정`으로 가격을 부여할 수 없다. 상품·국가·시장금리·ECL 시나리오 설정은 웹 대시보드에서 관리할 수 있다. 그 밖의 운영 데이터는 권한·불변조건을 확인하고 수정해야 한다. 모든 변경과 국가 거래는 `admin_audit`에 기록하며 비밀번호는 기록하지 않는다.

관리자 작업 기록은 데이터베이스 트리거와 웹 대시보드 양쪽에서 수정·삭제할 수 없다(append-only). KYC의 만료일이 지난 확인 완료 건은 준법 화면의 **만료 처리 실행**으로 최대 500건씩 상태를 만료로 전환하고 검토자·시각·사유를 별도 이력과 관리자 감사 기록에 남긴다.

웹 대시보드의 **KYC · AML** 화면에서 개인정보 원본 없이 KYC 상태·사유 코드, 국적별 AML 경보 임계치, ECL 낙관·기준·하방 시나리오를 관리하고 최근 평가 및 변경 이력을 확인한다. KYC 프로필이 명시적으로 있는 사용자는 확인 완료·만료 전이며 제한 등급이 아닐 때 송금, 예금 계좌 개설, 대출 신청을 할 수 있고 수취는 계속 가능하다. KYC에 의해 차단된 시도는 요청 종류와 고정 사유 코드가 수정 불가능한 KYC 이벤트 이력에 남아 관리자 타임라인에 표시된다. KYC 프로필이 없는 기존 사용자는 기존 동작을 유지한다. HTS 지갑에는 본인의 KYC 상태·위험등급·만료일을 표시한다. AML 감시는 개인 송금의 송금인·수취인 양쪽에 적용되며, 24시간 누적은 양방향 송금액을 해당 사용자의 국적 통화로 환산한다. 누적액 경보의 금액에는 경보 시점의 24시간 총액이 표시된다. AML 금액은 규칙의 국적 통화 정밀도, ECL 금액은 대출 통화 정밀도로 표시한다. 외화 거래 이력은 현재 과거 시점 환율을 저장하지 않으므로, 지난 거래는 경보 평가 시점 환율로 환산한다. **은행 원장** 화면은 금융기관 issuer를 지정해 통화별 시산 잔액, 불균형 분개, 기존 손익원장 대사와 예금보험 청구-분개장 대사를 조회한다. 은행 원장·준법·고객 목록/상세·DR 전환 원장을 열람한 관리자 ID와 최소 조회 필터는 감사 이력에 남기며, 고객 검색어는 저장하지 않는다. 개인 HTS 지갑에는 예금보험 정리 시 원예금 통화 기준 보장액·미보장채권과 실제 지급 통화·금액을 함께 표시한다. 실제 지급 통화가 다른 경우 지급액이 원예금 통화 기준 보장액과 다를 수 있고, 구형 이력에는 지급 상세가 비어 있을 수 있다. **종목·상품** 화면은 DR 생성·종료·시뮬레이터 보관량 대비 필요량 경고와 최근 전환 원장 100건을 읽기 전용으로 보여준다. 이 기능들은 운영 시뮬레이터 통제이며 규제기관 인증·회계감사 의견을 의미하지 않는다.

## 국가 명의 거래

지원 기능은 `$계좌개설`, `$계좌해지`, `$내지갑`, `$내주문`, `$대출`, `$대출연장`, `$대출상환`, `$도움말`, `$매도`, `$매수`, `$선물증거금`, `$송금`, `$옵션작성`, `$옵션체인`, `$주총`, `$펀드가입`, `$펀드환매`, `$환전`이다. 관리자가 아닌 국가 `users.user_id=20230216`의 잔액·보유자산·담보로 실행한다. 국가는 일반 사용자와 같은 거래소에서 거래한다.

조회는 DM으로 바로 표시한다. 입력이 필요한 기능은 인자 없이 실행하면 DM 버튼과 입력 모달을 제공하며, 일반 기능은 모달 순서와 같은 인자를 채팅에 입력해 실행할 수도 있다. `$주총`은 인자 없이 실행한 뒤 DM 모달을 사용한다. 예: `$매수 INZST001 2 1200`, `$송금 수신자 1000`, `$환전 기준 통화 USD 10000`. 국가와 일반 사용자 모두 지갑 조회 이름은 `내지갑`이다.

## 상품 카테고리와 그래프

`/검색`의 첫 화면은 **메인**이며 카테고리와 카테고리별 종목 수만 표시한다. 주식·ETF·국채·회사채·주식 선물·원자재 선물·일반 펀드·인덱스 펀드·현물 원자재·옵션·외환·외환통장·저축·대출상품을 개별 카테고리로 조회한다. 전체요약·주식 외 투자상품·내 통장·보유자산·개인 대출 카테고리는 제거했다. `/국채` 목록은 `/검색`의 국채 카테고리로 통합했다.

기본 상품은 각 카테고리 25개, 총 325개다. 여기에 외화 결제 주식·현물 원자재 50개를 별도로 추가한다. 모든 이름·가격·환율은 게임용 설정이다. 기본 옵션 25개는 국고가 작성한 커버드 콜이며, 각각 담보 주식 100주와 매도 호가가 있다. 새 상품이 추가될 때 기존 사용자의 잔액·상품 설정을 덮어쓰지 않는다. 기존 코드가 기본 코드와 충돌하면 일괄 추가를 중단하고 전체를 롤백한다. 기본 발행은 국가가 새 주식을 발행하는 게임 내 상장이며 현실 상품의 권리를 나타내지 않는다.

`/그래프 종목:INZOP001`처럼 첫 번째 인자에 종목 코드를 반드시 입력한다. 종목 선택 셀렉박스와 자동완성은 사용하지 않는다. `/매수`·`/매도`·`/호가`·`/선물증거금`·옵션 기초주식도 코드를 직접 입력한다. 펀드는 `/매수`·`/매도`에서 지정가를 생략하고 NAV로 거래한다. 코드는 `/검색`에서 확인한다. 금리는 `기준금리`·`법정최고이자`를 입력할 수 있다. 옵션과 국채는 거래가 없더라도 현재 시세를 매초 기록한다.

| 그래프 선택 | 캔들·집계 주기 | X축 총 표시 기간 |
|---|---|---|
| 1분 | 1분봉 | 10분 |
| 5분 | 5분봉 | 1시간 |
| 10분 | 10분봉 | 6시간 |
| 30분 | 30분봉 | 12시간 |
| 1시간 | 1시간봉 | 1일 |
| 6시간 | 6시간봉 | 1일 |
| 12시간 | 12시간봉 | 1일 |
| 1일 | 일봉 | 1일 |

선택값은 OHLC·거래량·지표의 집계 주기이며, X축은 위 표의 총 표시 기간만큼 보여준다. 선택 메뉴 설명과 그래프 임베드에도 해당 총 기간을 함께 표시한다.

한국시간 날짜가 바뀌면 과거 가격/거래/지수 로그는 정리하며, 잔액·주문·계약·금리 이력·환전 거래 원장·복권 기록은 보존한다. 따라서 6시간·12시간·1일 그래프에서도 당일 저장된 기록만 표시될 수 있다.

## 사건과 가격

`$사건` 버튼은 종목, duration(초), 호재/악재, 0~100%, 선택 목표가격의 다섯 항목을 가진 모달을 연다. 목표가격이 없으면 시작가에서 호재 +N%, 악재 -N%를 최종 목표로 잡는다. 목표가격을 입력하면 %는 중간 흔들림의 강도다.

가격은 시작가와 목표가를 잇는 평균 변화율 선을 기준으로 위아래로 움직인다. 변동률이 클수록 기준선 주변의 편차가 커지며, 시작·종료 지점에서는 편차가 줄어들어 종료 시점에 정확히 목표가격을 적용한다. 반올림으로 아주 작은 가격 차이는 같은 호가로 보인다. GARCH 분산·공통 요인·자산별 충격·중복 틱 방지·재시작 복구는 유지한다.

같은 종목에 사건을 다시 등록하면 **기존 사건을 superseded로 중단하고 등록 순간의 현재가에서 새 duration·목표로 시작**한다. 다른 종목의 사건은 계속된다. 사건 기록은 삭제하지 않는다. 가격 고정 종목과 만료 상품은 제외하며, 옵션·국채는 계약상 가격 고정과 시장 프리미엄을 구분하여 개별 사건을 허용한다. ETF·선물·회사채·펀드도 개별 사건을 허용한다. 전체 시장 사건에서는 기존과 같이 독립 가격 종목을 대상으로 하며, 연결 상품은 기초 종목 변동을 반영한다.

사건은 채권 액면가·상환액, 옵션 행사가·담보를 변경하지 않는다. 지수/NAV 연동 상품은 사건 종료 후 기본 평가식으로 돌아가며, 옵션/국채의 사건 시장가격은 후속 사건 또는 거래/운영 변경 전까지 유지할 수 있다.

## 외환

`currencies`, `country_currencies`, `currency_products`, `currency_accounts`, `currency_transactions`가 동일 DB에 저장된다. 낙원의 기본 통화는 기준 통화이며 미국→USD, 대한민국→KRW 등은 **게임 설정**이다. 45개 가상 국가와 통화를 함께 준비했다. 기존에 통화가 매핑되지 않은 국적은 기준 통화를 기본으로 표시한다. 국적·통화 연결과 사용자 국적은 DB Browser의 `country_currencies`·`users`에서 관리한다.

```text
/검색
/내지갑
/계좌개설 상품:INZCU001
/송금 수신자:본인_USD_외환계좌번호 금액:3 출금계좌:__wallet__
/송금 수신자:본인_사용자_ID 금액:1 출금계좌:본인_USD_외환계좌번호
/내지갑
/그래프 종목:CUR_USD
```

출금/입금 통화의 외환통장은 먼저 개설한다. 금액은 통화별 `decimal_places`(최대 6자리)까지 지원하며 기준 통화는 0자리다. 1외화 단위당 기준 통화 시세가 실시간으로 움직이며, `$사건`의 `CUR_USD` 같은 종목으로 환율 목표를 지정한다. 환전 중 사용한 두 시세, 수수료, 차감·입금액은 하나의 트랜잭션에 저장한다. 잔액 부족이나 통장 미개설이면 모두 롤백한다. 같은 통화 환전은 거부하며, 입금액은 내림·수수료는 올림하여 반올림 차익을 막는다.

환전 수수료 기본값은 0.1%이고 국고에 입금된다. 외환통장은 상품 연이율에 따라 잔액을 늘리며 1마이크로 단위 미만 이자는 누적한다. `/내지갑`의 외환 평가액은 현재 환율을 적용한다. `/외환계좌`는 `/계좌개설`에 통합했고 상품 코드를 직접 입력한다.

외화 결제 주식 25개와 현물 원자재 25개를 추가했다. USD·EUR·JPY·GBP·KRW마다 각각 5개씩이며 `INZUSDST001`은 USD 주식, `INZUSDCM001`은 USD 현물 원자재다. 해당 통화의 외환통장을 먼저 개설하고 잔액을 준비한 뒤 `/매수`·`/매도`에서 거래한다. 지정가는 종목의 결제 통화 단위이며 기준 통화 지갑을 자동으로 사용하는 기능은 없다. 주문 예치·환불·체결 대금은 같은 외화로 처리하고, 순자산과 매도 실현이익 세금은 체결 시점 환율로 기준 통화 환산한다. 기존 상품은 기준 통화를 유지한다. 외화 결제는 주식·현물 원자재를 지원하며 옵션·주식 선물·회사채 발행은 기준 통화 기초주식만 지원한다. 결제 통화 `quote_currency`는 발행 후 변경할 수 없다.

공개 슬래시 명령어 `/외환입금`·`/외환출금`·`/환전`은 제거하고 `/송금`으로 통합했다. 수신자는 사용자 ID 또는 일반/외환 계좌번호, 출금계좌는 본인 계좌번호 또는 `__wallet__`이다. 본인 외환통장이 수신자이면 금액은 **입금될 외화 기준**이고, 그 외 송금은 **출금 통화 기준**이다. 통화별 `decimal_places`(최대 6자리)를 적용하며, 필요한 출금액은 환율·수수료·최소단위를 반영해 역산한다. 통화가 같으면 환전 수수료 없이 송금하고, 통화가 다르면 해당 시점 환율과 환전 수수료를 적용한다. 다른 사람의 출금계좌는 사용할 수 없고, 통장이 없으면 먼저 개설해야 한다. 일반통장 원금·이자 기준 시각도 함께 갱신하며 모든 차감·입금·수수료를 원자적으로 처리한다.

`/내지갑`에 국적·기본 통화와 일반/외환통장 번호·외화 잔액·기준 통화 평가액을 함께 표시한다. 통장·보유 종목·작성 옵션이 많으면 페이지로 전부 조회한다. 기존 옵션·국적·외환 개별 조회는 `/내지갑`에 통합했고, 국가 지갑도 `$내지갑`으로 조회한다. `/환율`은 `/검색`의 **외환** 카테고리로 통합했다. 환율은 **1 기준 통화 = 외화 금액**으로 표시하며 **10개 통화씩** 페이지를 넘긴다. 페이지 이동 시 최신 시세를 다시 읽으며, 표시 금액에는 환전 수수료를 포함하지 않는다. 예를 들어 1 USD가 1,600 기준 통화이면 1 기준 통화 = 0.000625 USD다. DB의 시세와 사건 목표가격은 기존대로 1외화 단위당 기준 통화를 사용한다.

옵션 작성 의무 평가는 작성한 옵션의 현재 의무 가치로, 순자산에서 차감하므로 음수로 표시한다. 옵션 프리미엄을 거래해도 커버드 콜 담보 주식은 계약이 끝날 때까지 잠겨 있어 매도할 수 없다. 담보 주식은 실제 기초주식 코드와 잠금 계약 코드를 표시하고 작성 계약·체결 수량·미체결 수량·담보·만기를 함께 보여준다.

복권 사용·관리 명령어와 추첨 검증은 [복권 운영 안내](lottery_operations.md)에 정리했다. 관리자는 `$복권가격설정`, `$복권당첨번호보기`, `$복권당첨번호변경`을 사용한다. 다른 회차 규칙은 DB의 `settings.lottery_config`에서 관리한다.

## DB 운영

이전은 모든 테이블·행·인덱스·트리거·AUTOINCREMENT 값을 임시 파일에 복사하고 건수·무결성을 검증한 뒤 원자적으로 `inazina.db`를 공개한다. 실패한 이전은 기존 DB를 변경하지 않는다. 단일 파일의 WAL, 공유 쓰기 잠금, 원자적 거래와 50ms 시장 갱신 대기를 사용한다. 외환 사용자/거래시간 인덱스와 기존 가격/거래 인덱스를 유지한다. 봇을 재시작하여 새 코드와 슬래시 목록을 적용하고, 이후 DB Browser도 새 파일만 편집한다.

실제 Discord의 버튼/모달 제출, Message Content Intent와 삭제 권한은 서버에서 확인해야 한다. 재시작 후 봇 사용자 이름도 Inazina로 변경을 시도하며, Discord가 제한하면 로그를 남기고 운영을 계속한다. 토큰은 `INAZINA_TOKEN` 환경변수를 사용하며, 기존 `NACONOMICS_TOKEN`도 이전 호환을 위해 지원한다.

## 내지갑 화면

`/내지갑`은 메인에서 국적·기본통화·현금·통장·외환·투자 평가액·주문 예치금·옵션 담보·옵션 작성 의무 평가·부채·순자산·신용점수와 카테고리별 항목 수를 보여준다. 선택 메뉴에서 통장·외환통장·주식·ETF·국채·회사채·선물·펀드·원자재·보유 옵션·작성 옵션·옵션 담보·대출을 나눠 보고, 10개씩 페이지를 넘긴다. 가격·잔액은 조회 시점 스냅샷이며 최신 값은 명령어를 다시 실행해 확인한다.

옵션 작성 의무 평가 박스는 메인과 작성 옵션 화면에 표시한다. 미만기 판매 옵션의 현재 프리미엄 × 미만기 체결 계약 수이며 순자산에서 차감한다. 만기에 이 평가액을 그대로 납부하는 의미는 아니다. 콜이 행사되면 담보 주식을 인도하고 행사가 대금을 받으며, 풋이 행사되면 담보금으로 행사가에 주식을 매수한다. 미행사 잔여 담보는 반환하고 이미 수령한 프리미엄은 유지한다. 매수 옵션을 재판매한 사용자는 작성자 의무가 생기지 않는다.

지갑 메인의 금액·신용점수는 코드 박스로 통일한다. 보유 카테고리는 통장·주식/ETF·채권·선물·펀드/원자재·옵션·대출 그룹의 아이콘과 보유 건수를 인라인 필드로 표시한다.

관리자 `$` 응답은 도움말·처리 중·결과·오류·모달 안내를 임베드로 통일한다. 성공은 초록색, 오류는 빨간색, 안내는 파란색으로 표시하고 긴 결과는 임베드 미리보기와 전체 텍스트 첨부 파일로 제공한다.

관리자 도움말은 상품·시민/잔고·시장/환율·도박/세금·금리·복권·사건·국가 기능을 별도 임베드 필드로 나눈다. 일반 응답은 처리 상태·명령어·상세 내용으로 구성하고 가격·잔고 변경은 대상과 변경 전후 금액 박스를 표시한다.

## 상품생성 인자 순서

공통 앞부분은 `$상품생성 [id] [상품종류]`이며, 아래 인자를 순서대로 입력한다. `id`는 다른 상품과 겹치지 않는 종목 코드로 이후 검색·거래·수정에서 사용한다. `상품종류`는 아래 표의 유형이며 뒤의 인자 순서를 결정한다. `[ ]` 기호는 직접 입력하지 않는다. 마지막 `[추가 JSON]`은 모든 유형에서 선택 사항이다.

### 주식예탁증서(DR)

`dr_dividend_tax_rules` 규칙은 **종목·상품 → DR 국경간 배당·원천징수** 관리자 화면에서 추가한다. 발행/상장국(기초 DR 거래소), 기초주 발행국(원주 거래소), 수익자 국적, 선택적 세무거주지, 상품 유형, 조약 코드, 세율·면세, 효력 시작/종료 epoch를 설정한다. 효력 구간은 `[시작, 종료)`이고 수익자 국적·거주지·상품 유형 `*`는 와일드카드다. 가장 구체적이고 해당 주주명부 기준일에 유효한 규칙을 적용하며, 규칙 변경은 기존 규칙 수정이 아니라 새 버전 추가로 처리한다. HTS 지갑에서 사용자가 세무거주지를 입력/변경할 수 있고, 해당 값은 다음 주주명부 확정 시점부터 DR 권리별 스냅샷에 반영된다(미입력 시 국적 대용). 사용자별 지급에는 DR 코드·선택 규칙 ID·관할·기준일·조약·세율·총액·세금·순액과 지급 통화를 불변 이벤트로 남기고, 원천징수액은 기초주 국가 국고로 귀속한다. 같은 통화에 여러 DR 프로그램과 원주가 함께 있어도 프로그램·원주별 지급행으로 나누어 각각의 세칙을 적용한다. 각 지급과 국고 송금은 상품 통화 최소단위의 `BankJournal` 복식 분개로 기록하며 관리자 웹에서 통화별 차변/대변 대사를 확인할 수 있다. 분개는 내부 시뮬레이터 원장이며 기존 도메인 현금/세금 기록과 실제 외부 송금은 별개다. 규칙·원천징수 이벤트는 DB 트리거로 갱신·삭제를 막고, 관리자 읽기/추가는 감사로그에 기록한다. 규칙이 없으면 기존 수익자 국적 기준 배당 세율을 적용한다. 세무거주지 입력은 자기신고일 뿐 증빙·법률상 거주자 판정은 하지 않으며, 이 체계는 실제 조세조약 자료·법률 판단·외부 송금 증빙과 연결되지 않는다.

`dr`은 별도 상장 자산(`market_assets`)으로 생성하며 기존 원주 회사 코드는 복제하지 않는다. 예시는 `$상품생성 KOCO_DR_LN dr "KOCO DR" 25 10000 LSE {"underlying_code":"KOCO","underlying_per_receipt":2,"quote_currency":"ABC","depositary_bank":"Example Depositary","custodian":"Example Custody","home_exchange_id":"KRX"}`이다. 같은 설정은 웹 대시보드의 **종목·상품 → 주식예탁증서(DR)** 화면에서 가능하다. 고급 설정 `settlement_delay_seconds`는 0~2,592,000초(최대 30일), `issue_fee_bps`와 `redeem_fee_bps`는 각각 0~10,000bp이며 기본 지연·수수료는 0이다. 지연을 설정하면 Discord `/dr전환`과 HTS에서 접수된 발행·상환 요청은 대기 상태가 되고 입력 원주/DR 수량이 매도·담보·다른 전환에 예약된다. 사용자는 HTS에서 상태·정산 가능 시각을 확인하고 취소할 수 있다. 만기 요청은 봇의 예약 작업 루프가 자동 정산하며, 관리자는 **종목·상품 → DR 내부 수탁 처리 이력**에서 대기 요청을 조회·취소하거나 수동 재처리할 수 있다. 정산 오류는 원자 롤백되어 입력 자산과 예약이 유지되며 자동 재시도 대상이 된다. 화면에는 요청별 시도 횟수와 최근 결과/오류 사유가 표시된다. 자동 정산은 요청당 실패 5회 후 중단하고, 관리자는 오류를 확인해 수동 재시도하거나, 제한된 사유 코드(compliance_review, invalid_program, insufficient_custody, operational_error, other)로 요청을 거절할 수 있다. 거절은 불변 이벤트에 사유를 남기고 예약 수량을 해제한다. 봇 프로세스가 꺼져 있으면 워커도 멈추므로 재기동 후 처리된다. 관리자 화면은 순발행량과 보유량, 예탁 원주·전환비율, 예약·요청 상태를 읽기 전용 대사하며 불일치를 자동 보정하지 않는다. 정산기한 24시간 경과 시 관리자 화면에 경고하고, 7일 경과 미처리 요청은 `expired_unsettled`로 자동 거절하며 예약을 해제한다. 발행·상환 수수료는 요청 시점 DR 가격과 수수료율을 고정하고, 정산 시 DR 호가통화의 currency_saving 계좌에서 통화 소수 자릿수에 맞춰 반올림해 차감한다. 해당 통화 계좌 잔액이 부족하면 전환·수수료·분개가 모두 롤백되고 요청은 실패 재시도 상태로 남는다. 수수료는 불변 fee ledger와 `DR_CUSTODY` 복식분개(customer_deposits_payable 차변, custodian_fee_income 대변)에 기록되며 관리자 대사 화면에서 원장 합계와 분개 합계를 비교한다. 원주는 활성 보통주여야 하고 활성 DR 프로그램들의 최대 예탁 용량 합계가 원주 발행량을 넘을 수 없다. 중지된 프로그램은 신규 발행만 막고 보유 DR의 상환·기초주 배당 권리는 유지한다. DR 이동은 참조키 기반으로 중복 방지하며 불변 수탁/전환 원장과 본인 HTS 이력에 기록한다. DR 가격은 참고가를 향한 연 25% 로그 평균회귀 압력을 받지만 페그·가격보장은 아니다. 기초주 배당은 주주명부 마감 시 DR의 원주 등가 수량을 포함해 계산하고, 다른 통화 지급은 현재 지급일 환율로 환산한다. 관리자는 관리자 화면에서 회의 기준 잔고 스냅샷·안건·투표 기간·정족수를 관리하며 결과를 조회하고, HTS 자격자는 가중 의결권으로 안건마다 기간 내 한 번 투표한다. 스냅샷은 과거 잔고 재구성이 아니라 생성 당시 현재 잔고 기준이며, 재투표·철회는 불가하다. 모든 기능은 내부 시뮬레이터 기록이지 실제 예탁기관·수탁사의 보관 증명이나 법적 의결 절차가 아니다. 보유·담보·미체결 주문·예탁 원주가 남은 DR 프로그램은 관리자 화면에서 종료할 수 없다. 미종료 DR이 연결된 원주는 액면분할·병합·합병할 수 없다.

기준일 스냅샷이 생성된 뒤 관리자는 `POST /api/admin/dr/voting-window`에 `{ "meetingId": 1, "opensEpoch": 1800000100, "closesEpoch": 1800003700, "quorumPercent": 30 }`을 보내 시작·마감 시각과 정족수(0~100%)를 한 번 설정한다. 시작 시각은 현재 시각과 기준일 이후여야 하며 설정은 변경할 수 없다. 이어 `POST /api/admin/dr/voting-agenda`에 `{ "meetingId": 1, "title": "배당안", "choices": ["찬성", "반대", "기권"] }`을 보내 안건을 등록한다. 의결권 보유자는 `POST /api/dr/votes`에 `{ "meetingId": 1, "agendaItemId": 1, "choice": "찬성" }`으로 투표하며 지정된 기간 안에 안건당 1회만 가능하다. HTS의 **주주총회 의결권** 영역에서 본인 안건·표수·투표 기간을 확인하고 선택지를 눌러 투표할 수 있다. 위임 포함 기준일 의결권 전체가 표 가중치로 사용된다. 관리자는 `GET /api/admin/dr/voting-results?meetingId=1`에서 선택지별 가중표수·투표자 수·투표율을 조회하고 마감 후 정족수 충족 여부를 확인한다. 일정·안건·투표는 수정·삭제할 수 없다. 재투표·투표 철회 및 역사적 기준일 잔액 재구성은 제공하지 않는다.

| `issuer` | 저축·대출 상품의 발행기관 이름. |
| `loan_limit` | 대출 한도. `0`은 한도 없음. |
| `min_credit_score` | 대출 신청에 필요한 최소 신용점수. |
| `underlying_exchange_id` | ETF·인덱스 펀드가 추종할 거래소의 ID. |
| `leverage_multiplier` | ETF의 추종 배율. `1`은 1배, `2`는 2배다. |
| `rebalance_cycle_seconds` | ETF 재조정 주기(초). |
| `underlying_code` | 선물·옵션의 기초 종목 ID. |
| `contract_size` | 선물 1계약에 해당하는 기초 종목 수량. |
| `initial_margin` / `maintenance_margin` | 선물 최초 / 유지 증거금 비율. `0.2`는 20%다. |
| `issuer_code` | 회사채를 발행할 회사의 종목 ID. |
| `face_value` | 채권 1개 만기 상환의 기준 액면가. |
| `components` | 펀드 구성 종목과 비중. `INZST001:0.5,INZST002:0.5`처럼 입력하며 합계는 1이다. 구성 종목은 활성 회사 주식이어야 한다. |
| `option_type` | 콜 `call` 또는 풋 `put`. |
| `strike_price` | 옵션 행사 가격. |
| `quantity` | 생성·매도할 옵션 계약 수. |
| `limit_price` | 작성한 옵션의 매도 지정가(계약당 프리미엄). |
| `volatility_percent` | 옵션 평가에 쓰는 변동성(%). |
| `asset_code` | 통화에 연결할 환율 자산의 종목 ID. 먼저 `asset` 유형에서 `type=forex`인 활성 자산을 생성해야 한다. |
| `nationality` | 해당 통화를 기본 통화로 연결할 국적. |
| `currency_code` | 외환통장의 통화 코드. 예: `USD`. |
| `extension_min_credit_score` / `extension_days` | 대출 만기 연장에 필요한 최소 신용점수 / 허용 연장일수. |
| `underlyings` | ELS의 활성 주식·거래소지수 코드 1~3개. `ST,__exchange_index__:INZ`처럼 쉼표로 구분한다. |
| `annual_coupon` | ELS 연 쿠폰(%). `12`는 연 12%다. |
| `observation_days` / `redemption_levels` | ELS 발행 후 조기평가일수 / 해당 회차 상환 기준(%). 예: `30,60,90` / `90,85,80`. |
| `maturity_level` / `knock_in_level` | ELS 만기 상환 / 낙인 기준(%). 최초기준가에 대한 비율이며 낙인 기준은 만기 기준 이하다. |
| `subscription_days` | ELS 생성 후 모집 기간(일). 실제 발행은 모집 종료 후 다음 유효 가격 틱이다. |

예를 들어 `$상품생성 ST company "배당 회사" 게임 1000000 10000 100 INZ 1주 5`는 종목 ID `ST`, 주식, 이름 `배당 회사`, 업종 `게임`, 자본금 1,000,000 기준 통화, 10,000주 발행, 주가 100 기준 통화, 거래소 `INZ`, 매주 주당 5 기준 통화 배당을 뜻한다.

국채 예시에서 `$상품생성 GB bond "새 국채" 1000 100000 1000 3 90 BOND`는 1매 가격 1,000 기준 통화, 총 액면 발행한도 100,000 기준 통화, 액면가 1,000 기준 통화, 발행 100매, 연이율 3%, 만기 90일을 뜻한다.

변동금리 예금 예시는 `$상품생성 FLOAT saving "변동 예금" 5 1000 365 86400 1 은행 {"rate_type":"floating","rate_nationality":"낙원","benchmark_key":"funding","benchmark_tenor_days":365,"repricing_cycle_seconds":2592000}`이다. 생성 시 입력한 광고금리에서 당시 365일 조달금리와 기타 상품 조정을 뺀 값이 `base_rate_spread`로 저장되고, 이후에는 30일마다 지정한 관측시점의 조달금리로 계약금리를 다시 정한다. `base_rate_spread`를 JSON에 직접 넣으면 입력한 `interest_rate`보다 가산금리를 우선한다.

HTS 지갑의 활성 예금 계좌와 대출 일정에는 현재 계약금리, 지표 관측 기준일, 다음 재산정일, 기준지표와 만기를 표시한다. 예금 계좌는 최근 3건의 실제 금리 재산정 이력도 볼 수 있다. 관측이 끝나기 전에는 다음 금리를 확정값으로 제시하지 않는다. 이는 화면 안내이며 별도 사전 통지·수신 확인 절차는 아직 없다.

옵션 생성은 국가 명의로 담보를 설정하고 매도 지정가 주문을 등록한다. 콜은 계약당 기초주식 1주, 풋은 `행사가 × 계약수`만큼 국고 현금이 필요하다. 기초자산은 기준 통화 결제 활성 주식만 지원하며 만기는 1~365일, 평가 변동성은 1~500%다. 선물·회사채의 기초/발행 회사도 기준 통화 결제 활성 회사 주식이어야 하며 만기는 1~3650일이다. 선물 증거금은 `0 < 유지증거금 ≤ 초기증거금 ≤ 1`로 입력한다.

`company`, `preferred`, `asset`, `etf`, `fund`, `indexfund`, `commodity`는 위 기본 인자 뒤에 선택 인자 **`[정규배당주기] [주당 배당금 또는 비율%]`**을 함께 입력하거나 함께 생략한다. `5`는 1주당 고정 5, `5%`는 지급 시점 가격의 5%다. 두 방식을 동시에 적용하지 않는다. 이 비율은 기업 이익 중 배당 비중을 뜻하는 배당성향이 아니라 **가격 기준 비율배당**이다. `asset`의 배당은 주식(`stock`/`주식`)과 현물 원자재(`commodity_spot`)만 지원한다. ETF·펀드·현물 상품은 1좌/1단위당 금액 또는 가격을 기준으로 한다. 채권은 계약 이자, 선물·옵션은 계약 정산을 사용한다.

- 정규배당주기: DB 컬럼 `dividend_cycle_seconds`. 초 단위 숫자 또는 `1일`, `1주`, `1달` 입력. `1달`은 고정 30일이다.
- 배당 방식: DB 컬럼 `dividend_mode`. `fixed`는 주당 고정금액, `percent`는 지급 시점 가격 기준 비율배당이다. 기존 상품의 기본값은 `fixed`다.
- 주당 고정 배당금: DB 컬럼 `dividend_per_share`. 상품의 결제 통화 기준 0 이상의 정수이며 `fixed` 방식에서 사용한다.
- 가격 기준 배당 비율: DB 컬럼 `dividend_percent`. 0~100%이며 소수 입력도 가능하다. `5%` 입력은 `percent` 방식과 비율 `5`로 저장한다.
- 정규배당 활성: DB 컬럼 `dividend_is_active`. `1`은 ON, `0`은 OFF이며 기본값은 `1`이다. 기존 상품의 다른 활성 상태와 구분한 배당 전용 스위치다.
- 다음 지급 시각: DB 컬럼 `dividend_next_epoch`. 생성·설정 시점 + 주기로 자동 예약한다.
- 생성 시 배당 선택 인자를 생략하면 고정금액 `0`(배당 없음), `$상품수정`에서 생략하면 기존 배당 설정을 유지한다. 주기가 `0`이거나 선택한 방식의 금액·비율이 `0`이면 자동배당이 지급되지 않는다.
- `loan`은 별도로 `[extension_min_credit_score] [extension_days]`를 선택 입력한다.

배당 컬럼은 단일 `database/inazina.db`의 `company`, `market_assets`, `investment` 테이블에 저장된다. 기존 DB도 봇 시작 시 누락된 컬럼을 자동으로 추가한다.

```text
$상품생성 ST company "배당 회사" 게임 1000000 10000 100 INZ 1주 5
$상품생성 PR preferred "배당 회사 우선주" ST 100000 1000 90 INZ 1주 7
$상품생성 CM commodity "현물 상품" 100 1000 COM 1일 2
$상품생성 PC company "비율 배당 회사" 게임 1000000 10000 100 INZ 1주 5%
$상품생성 OFF company "배당 중지 회사" 게임 1000000 10000 100 INZ 1주 5 {"dividend_is_active":0}
$정기배당수정 ST 1달 10
$정기배당수정 ST 1주 5%
$정기배당활성 ST off
$정기배당활성 ST on
$특별배당실시 ST 20
```

`$정기배당수정 ST 1주 5%`는 매주 가격 기준 5% 배당으로 바꾸고, `ST 1주 5`는 매주 주당 고정 5 배당으로 바꾼다. `$정기배당활성 ST off`는 주기·방식·금액·비율을 유지한 채 다음 예약을 비운다. `on`으로 다시 켜면 명령 실행 시점부터 한 주기 뒤 첫 지급을 예약하며 중단기간의 배당을 소급 지급하지 않는다. OFF 상태에서 `$정기배당수정`으로 설정을 바꿔도 OFF는 유지된다. 특별배당은 이 스위치와 무관하게 `$특별배당실시`의 주당 고정금액으로 지급한다.

DB Browser에서 `dividend_is_active`를 직접 변경할 수도 있다. 활성값 변경 시 DB 트리거가 기존 지급 예약을 비운다. 직접 ON으로 바꾸면 다음 배당 작업 처리 시점부터 한 주기 뒤를 예약한다. `/검색`은 주기·금액 또는 비율이 설정된 OFF 상품에 **정기배당 OFF · 지급 중지**를 표시한다.

정기배당은 지급 시점 보유량을 기준으로 계산한다. 고정금액 방식은 `보유량 × 주당 고정 배당금`, 비율 방식은 `보유량 × 지급 시점 주가·상품가격 × 배당 비율 / 100`이다. 비율 방식은 사용자별 보유량을 합산한 뒤 세전 지급액을 정수 통화 단위로 반올림하며 0.5는 올린다. 예를 들어 가격 103 기준 통화, 3주 보유, 비율 5%라면 세전 배당은 `103 × 3 × 0.05 = 15.45`를 반올림한 15 기준 통화다. 국고 재원에서 지급하고 세금을 원천징수한다. 기준 통화 배당은 지갑, 외화 배당은 해당 외환통장에 입금한다. 매도 주문으로 잠긴 수량과 콜옵션 담보 수량도 소유자의 배당 대상이다. 국고 보유 수량은 지급 대상에서 제외한다. 재원 부족이면 해당 회차 전체를 취소하고 다음 처리에서 재시도한다. 봇 재시작 후에도 회차별 중복 지급을 방지하며, 누락된 회차는 한 번의 처리에서 종목당 최대 20회씩 따라잡는다. 누락 회차의 비율배당은 재처리하여 실제 지급하는 시점의 현재가격을 사용하며 과거가격을 복원하지 않는다.

회차 기록은 `dividend_distributions`, 사용자별 수령 기록은 `dividend_payments`에 저장된다. 회차별로 배당 방식·기준가격·비율을 확정해 저장하므로 이후 가격이나 설정이 바뀌어도 이미 지급한 내역의 계산 근거는 유지된다. 현재 배당 지급 시 가격을 자동으로 배당락 조정하지는 않는다.

법인 재원 배당은 `company.dividend_funding='issuer'`로 지정한다. 보통주와 연결 우선주가 공유하는 `issuer_cash_accounts`에 `$법인잔고수정`으로 현금을 확보한다. 우선주 `dividend_priority`, `cumulative_dividend`, `liquidation_value_per_share`로 지급 우선·미지급 누적·청산 우선한도를 설정하며, 확정 채권은 `preferred_dividend_claims`에 수령자별로 보존한다. 같은 법인의 보통주보다 우선주를 먼저 지급하고 누적형의 부족액은 채권으로 남긴다. 이 경로는 위 국고 배당의 회차 전체 재시도와 구분한다.

ELS는 `/매수`에서 모집 중 액면으로 청약하고 청약 원금·발행자 최대 쿠폰을 예치한다. 모집 종료 후 최초기준가를 확정하며 이후 추가 청약·매도·중도환매를 허용하지 않는다. `/검색`·`/내지갑`에 ELS 카테고리, `/그래프`에 기초자산 선택·상환·낙인 기준선을 제공한다. 발행 조건·평가·낙인·정산 이력은 차트 일일 삭제 대상에 포함하지 않는다. 상세 생성 예시·법인 청산·상환 규칙은 [우선주·ELS 운영 안내](preferred_and_els_plan.md)를 참고한다.

```text
$상품생성 FIX company "고정 주식" 게임 100000000 100000 1000 INZ {"is_fixed":1}
$상품생성 FUND fund "주식형 펀드" 1000 10000 INZST001:0.6,INZST002:0.4 INZ {"fund_category":"equity"}
```

일반 펀드는 주식(`company`), 회사채(`corporate_bond`), 국채, 현물 원자재(`commodity_spot`),
부동산(`real_estate`), 특별자산(`special_asset`)을 구성 자산으로 사용할 수 있다. `fund_category`는
`equity`(주식 60% 이상), `bond`(채권 60% 이상), `mixed`(주식·채권을 모두 편입하고 합계 60% 이상),
`other`(그 밖의 대체자산 중심) 중 하나다. 생략하면 목표 비중으로 자동 판정하며, 명시한 유형과
구성 비중이 다르면 생성·수정을 거부한다. 현재 인덱스 펀드는 주식 거래소 지수를 추종하므로
`equity`만 지원한다.

### 펀드 AUM과 현금 원장의 범위

신규 관리자 생성·발행·카탈로그 펀드는 기준 통화 실보유형이다. `fund_accounts`에 전용 계정을 만들고,
`__fund__:<펀드코드>`를 주문·보유자산의 소유자 식별자로 사용한다. 기존 테이블의 `user_id` 컬럼을
재사용하지만 `users`에는 행을 만들지 않는다. 따라서 시민 수·기본소득·사용자 로그인 대상이 아니며,
이 식별자로 시민을 생성하는 작업도 DB에서 거부한다. 구성자산은 `user_assets`, 국채는
`treasury_bond_holdings`에 보유하여 기존 매매·배당·채권 정산 기능과 공유한다.

관리자 대시보드 → 종목·상품 → 해당 펀드의 **펀드 운용**에서 현금·실제 보유자산·미체결 주문·원장을
조회하고 구성자산 지정가 매수/매도 및 주문 취소를 할 수 있다. 가입만으로 자동 매수하지 않는다.
일반 펀드는 설정된 구성자산만 매수하고, 인덱스 펀드는 기초 거래소의 활성 회사 주식을 매수한다.
리밸런싱 버튼은 현재 시점의 목표 비중과 실제 평가액을 비교하여 초과 자산을 먼저 매도하고,
체결 후 사용 가능 현금으로 부족 자산의 지정가 매수 주문을 낸다. 주식형 등 정수 거래 자산의
최소 주문 단위와 발행량 한도 때문에 작은 비중 차이는 남을 수 있다. 미체결 주문이 있으면 재실행을
막아 중복 주문을 방지한다. 인덱스 펀드는 기초 거래소의 현재 시가총액 비중을 목표로 사용하며,
다른 펀드는 저장된 구성 비중을 목표로 사용한다. 일부 주문 거절·미체결 여부를 실행 결과에 표시한다.
리밸런싱은 운용 화면의 버튼으로 실행하며 정기 자동 실행은 하지 않는다.

가입금은 국고가 아닌 해당 펀드에 적립한다. 매수 주문 때 사용 가능 현금을 예약하고 실제 체결된
수량만 보유한다. 가격 개선분·취소 예치금은 같은 펀드로 반환한다. 현금 원장은 사용 가능 현금의
변동을 추가 기록하며 UPDATE/DELETE를 금지한다. `원장 증감 합계 = 사용 가능 현금`으로 대사한다.
주문 예약은 아직 비용이 아니므로 NAV에는 예약금도 포함한다. 원장과 주문/체결 내역을 함께 조회한다.
펀드 현금 원장은 `FundCashLedger`가 관리하고, 잔액·전기·감사내역을 펀드별·통화별 최소단위로 보관한다.
기준 통화 잔액은 기존 매매 경로와 호환되며, 외화 배당 수령은 `FundDividendReceiver`가 해당 통화 원장에
기록한다. 외화 현금은 환산 평가액으로 NAV에 포함되지만 현재 구성자산 주문에 직접 쓸 수는 없다.

현재 지원하는 무차입 모형에서 `순자산 = 보유자산 평가액 + 사용 가능 현금 + 주문 예약금 + 미수 우선배당`,
`좌당 NAV = 순자산 ÷ 실제 발행좌수`이다. `total_supply`는 발행 한도이지 실제 발행좌수가 아니다.
주가·채권 가격만 변하고 보유 수량이 없으면 펀드 가치가 오르지 않는다. 가입·환매 직전에는 실보유
기준으로 다시 평가하고, 정수/소수점 좌수를 동일한 정산 경로로 처리한다. 기준 통화 금액은 정수이며
가입 대금은 올림, 환매 대금은 내림한다. 발행좌수가 0이면 계정에 저장한 최초 기준가격을 사용한다.

배당·채권 쿠폰·상환금은 펀드 현금으로 받으며 시민 소득세를 펀드 내부에서 중복 부과하지 않는다.
투자자 환매 차익·분배금에는 기존 투자자 과세를 적용한다. 펀드 분배금 재원도 국고가 아닌 펀드 현금이다.
환매금과 좌수는 같은 트랜잭션에서 처리한다. 현금 부족 시 환매 전체를 거절하며 좌수도 차감하지 않는다.
운용자가 자산 매도를 체결하거나 매수 주문을 취소한 뒤 투자자가 재요청한다. 자동 환매 대기열은 없고,
마지막 좌수는 보유자산·예약금·미수금을 정리한 후 환매한다. 장외 실물 매입이나 외부 증권사 연동이
아니라 게임 내부의 기존 거래소에서 체결하는 기능이다.

기존 가격추종형 펀드는 자동으로 전환하지 않는다. 펀드 운용 화면에서 기존 발행좌수와 기준가격에
따른 전환 필요액을 확인하고 **자금 이전 및 펀드 계정 개설**을 명시적으로 승인하면, 관리자가 국고에서
그 금액을 펀드로 이전한다. 국고가 부족하거나 확인한 전환 금액이 바뀌면 전체 취소된다. 좌수는 유지되며
중복 전환 요청은 재차 이체하지 않는다. 전환 후 구성자산 매수는 별도로 진행한다. 자동 역전환은 없다.

관리 API는 `GET /api/admin/funds/{code}`와 `POST /api/admin/funds/{code}`이며 POST 작업은
`activate` (`expectedFunding`), `order` (`assetCode`, `side`, `quantity`, `price`), `cancel` (`orderId`)이다.
공개 API는 관리자 인증을 요구하고 내부 운용 서비스도 관리자/지정 운용자 권한을 검사한다.
기존 보유분 전환에 필요한 국고 자금 이전은 관리자만 가능하다.

`add`는 현재값에 value를 더하고, `del`은 현재값에서 value를 빼며, `modify`는 현재값을 value로 설정한다. 값이 허용 범위를 벗어나면 변경하지 않는다. `$도움말`/`$help`는 상품·시민/잔고·시장/환율/사건·도박/세금·금리·복권·국가 기능의 7개 상세 페이지와 첫 메인 페이지를 선택 메뉴와 이전/다음 버튼으로 조회한다.

`$도움말`의 첫 페이지는 **메인**이며 카테고리 목록만 표시한다. 카테고리를 선택하거나 다음 버튼을 누르면 명령어·인자 설명을 확인한다.

## 문서·약관 편집

대시보드 **문서 · 약관**에서 `apps/site/public/links/`의 privacy·terms·operations·internal·help와
`database/private.text`(Discord 등록 안내문)를 고친다. 수정 → **변경 내용 확인**(바뀐 줄, 적용 시각,
등록 안내문의 모달 길이) → **확정** 순서다. 편집을 시작한 뒤 파일이 바뀌었으면 저장을 거부한다.

- 처리방침·이용약관·운영규칙·내부규칙은 확정 즉시 **개정 예정**으로 공지된다. 개정안은
  `<이름>.next.txt`, 적용 시각은 `pending.json`에 저장되고 공식 사이트 문서 창에 안내와 개정안 보기가 뜬다.
  공지 기간(7일, "이용자에게 불리하거나 중요한 변경"을 고르면 30일)이 지난 날 0시(한국시간)에
  Python 서비스가 1분 간격으로 확인해 개정안을 현재 문서로 바꾼다. 그 전까지는 현재 문서가 적용된다.
  개정안의 `시행일:` 줄은 적용일로 자동으로 채워진다. 다시 확정하면 개정안과 적용일이 새로 정해지고,
  **개정안 거두기**로 공지를 취소할 수 있다.
- 도움말과 등록 안내문은 확정하면 바로 바뀐다.
- 바뀌기 전 문서는 `database/document_history/<문서>/`에 보관하고 `document.announce`·`document.save`·
  `document.apply`·`document.cancel` 작업 기록을 남긴다.
- 공식 사이트를 개발 서버(`npm run dev:site`)로 띄우면 바로 반영된다. `vite build` 결과물로 배포하는
  경우에는 다시 빌드해야 한다.

게시판 글쓰기는 2026-10-17부터 열려 있으며, 약관 개정은 게시판을 닫지 않는다.

## 게시판 정지 · 비밀게시판

게시판 관리에서 게시판을 **정지**하면 읽기와 신고만 되고 글·댓글·반응·투표·수정은 막힌다(관리자는 계속
쓴다). 해제 예정 시각을 정하면 그때 자동으로 풀린다. **비밀게시판**은 허용 목록의 Discord 아이디와
관리자만 목록·글·첨부를 보고 쓸 수 있으며, 그 밖의 사람에게는 없는 게시판처럼 보인다.

## 뉴스 (시장 영향이 있는 게시글)

기본 게시판 **뉴스**(관리자만 작성, 종목 코드 허용)처럼 "뉴스"로 표시한 게시판에서 관리자는 글에
**시장 영향**(호재/악재, 강도 %, 영향 시간, 대상 종목 또는 시장 전체, 목표가)을 넣을 수 있다.
게시하는 순간 그 조건으로 시장 사건을 등록하고 글과 연결한다(`board_news`). 사건을 등록할 수 없으면
글을 올리지 않고 이유를 알린다. **예약 게시**는 정한 시각까지 관리자에게만 보이며, Python 서비스가
15초 간격으로 확인해 사건 등록과 공개를 함께 한다. 예약 시각에 등록이 실패하면 글은 숨겨진 채
'게시 실패'로 남는다. 뉴스를 삭제·숨김(관리자 숨김, 영구 삭제, 신고 3건 자동 숨김 포함)하면 연결된
사건을 그 시각에 끝낸다. 이미 움직인 가격은 되돌리지 않는다. 일반 이용자에게는 뉴스라는 표시만
보이고 방향·강도는 관리자만 본다. 좋아요·싫어요·댓글·답글은 다른 글과 같다.

뉴스로 만든 시장 사건은 **중첩**(`market_events.stacking=1`)된다. 같은 종목에 뉴스가 여러 개면 서로를 끝내지
않고, 시세 엔진이 갱신마다 진행 중인 각 사건의 그 구간 진척 비율을 곱해 현재가에 반영한다(+10% 두 건 ≈ +21%).
뉴스 하나를 지우면 그 몫만 빠지고 나머지는 계속된다. 대시보드 **시장 사건**에서 직접 거는 일반 사건은 예전처럼
그 종목에서 진행 중인 사건(뉴스 포함)을 모두 대체한다. 중첩 중인 종목은 사건별 무작위 흔들림 없이 각 사건의
평균 경로대로 움직인다.

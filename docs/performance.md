# 성능 최적화 기록

옵션 행사 대사는 현금 연결을 행사 키별로 조회한다. 연결 테이블에 `event_key` 인덱스를 추가해 행사 수가 늘어날 때 매 행사마다 전체 테이블을 훑지 않도록 했다. 임시 SQLite 메모리 DB에서 5만 행과 1,000회 조회를 5회 반복한 중앙값은 인덱스 전 1,920ms, 후 3.1ms였다. 실제 운영 환경의 전체 응답시간을 측정한 결과는 아니다.

2026-11-08 가격 계산을 다시 컴파일하고 운영 DB의 읽기 전용 복사본으로 비교한 결과, 전체 갱신 중앙값은 Python 198ms, Cython 193ms였으나 시뮬레이션 상태의 부동소수점 값이 정확히 일치하지 않아 동등성 검사를 통과하지 못했다. 이 결과로 기본 실행 경로를 바꾸지 않았다. 벤치마크는 현재 Python 소스와 바이너리의 해시가 다르면 측정을 거부한다.

디스코드 응답, 가격 갱신, 가격 계산 가속에 관한 설계와 측정 기록이다.

## 명령어 조회·차트 최적화

### Discord 전송 경로 개선

- `/내지갑`·`/검색`의 조회/화면 준비와 일반 검색 페이지 전환은 0.4초 이내에
  준비되면 바로 응답한다. 더 걸리면 먼저 defer하고 작업 완료 후 응답한다.
  `/그래프`와 차트 조작·실시간 순위 조작은 기존처럼 먼저 defer한다.
  초기 사용자 확인은 기존 `_prepare`에서 수행한다. 모달 열기 경로에는 자동 defer를 적용하지 않는다.
- defer로 생성한 최초 응답은 `edit_original_response`로 완성한다. 메시지를
  가져오는 GET은 추가하지 않으며, 완료 후 별도의 추가 알림은 followup으로 보낸다.
- 차트 이미지의 SHA-256과 기존 `movement.png` 첨부 유무를 확인한다. PNG가 같으면
  첨부를 유지한 채 임베드/컨트롤만 편집한다. 이미지가 다르거나 첨부가 없어졌으면 업로드한다.
  업로드 성공 후에만 해시를 갱신한다. 현재 시각·지표·고가/저가·거래량 등이 달라져 이미지가
  바뀌면 새로 업로드하므로, 단순히 현재가가 같다는 이유로 오래된 이미지를 쓰지 않는다.
- 차트 요청마다 선택 상태를 복사하고 한 View 안에서 직렬 처리한다. 연속 클릭 중
  대기 중인 이전 요청은 건너뛰며, 이미 계산 중이던 결과도 최신 선택이 아니면 전송하지 않는다.
  지표/VWAP 설정 저장은 ACK 이후 작업 스레드에서 처리한다.
- 설치된 discord.py는 HTTP 429의 `retry_after`, 서버 오류, 일부 연결 오류에 대한
  내부 재시도를 이미 수행한다. 그 위에 있던 추가 전송 재시도를 제거하여, 라이브러리가
  최종 실패를 반환한 뒤 메시지 전송 전체를 다시 시작하지 않는다. 금융 작업을 재실행하지 않는다.
- `inazina.performance`에 `discord.ack`, `discord.response`, `discord.complete`,
  `discord.followup`, `discord.edit`, `discord.chart_edit`를 기록한다. 100ms 이상 또는
  실패한 호출만 남긴다. 시간에는 네트워크와 라이브러리의 요청 대기/재시도가 포함되며,
  순수 회선 지연이나 사용자 화면에 표시되는 시각을 측정하는 것은 아니다.

통신 테스트에서는 빠른 조회의 defer 생략, 느린 조회의 선행 ACK, 최초 응답 편집,
첨부 유지/변경/실패, 연속 클릭의 오래된 결과 억제, 중복 재전송 방지를 검증했다.
실제 Discord 메시지 전송이나 운영 봇 재시작은 수행하지 않았다.
기존 지갑의 View 데이터 및 PNG 캐시를 재사용하며, 실시간 검색 결과를 오래 보관하는 캐시는 추가하지 않았다.

참고: [Discord 응답 기한](https://github.com/discord/discord-api-docs/blob/main/developers/interactions/receiving-and-responding.mdx),
[원본 응답 편집·첨부 API](https://discordpy.readthedocs.io/en/stable/interactions/api.html#discord.Interaction.edit_original_response),
[discord.py 전송·재시도 구현](https://github.com/Rapptz/discord.py/blob/master/discord/webhook/async_.py).

### 2026-10-09 추가 적용

- 전체 종목 목록은 종목마다 조회하는 대신 한 읽기 스냅샷에서 9개 SQL로 구성한다.
  전역 코드 중복 검사, 만기 상태, 옵션 이론가·최근 체결가·사건 가격 우선순위를 유지한다.
- 환율은 통화와 연결 자산을 JOIN한 요청별 스냅샷으로 평가한다. Fraction/Decimal과
  통화별 소수 자릿수·절삭·한도 검증을 유지한다. 지갑의 외환통장·현금에도 같은 스냅샷을 쓴다.
  다음 요청에서는 다시 조회하므로 DB Browser 변경이 반영된다. 거래·정산에는 적용하지 않는다.
- 검색의 환율·금리·지수·저축·대출 페이지는 불필요한 전체 종목 조회를 생략한다.
- 지갑 텍스트 준비를 작업 스레드로 옮겼다. 우선주 여부도 보유자산 일괄 조회에 포함하여
  Discord 이벤트 루프에서 종목별 회사 조회를 하지 않는다. 사용하지 않는 상세 임베드 생성도
  제거하여 메인 요약에 보유 내역이 섞이던 얕은 복사 문제를 해결했다.
- 주식·상품·거래소 지수 그래프는 기존 코드/시각 인덱스로 SQL OHLC를 집계한다.
  화면 경계 안 첫 가격과 원본 기록 수를 함께 읽고, 현재가를 마지막 봉에 반영한다.
  지표 준비 기간, 거래량, 매물대용 원본 체결, VWAP, ELS 기준선은 유지한다.
  PNG 캐시 키에 OHLC도 포함하여 고가·저가만 바뀌어도 새로 그린다.
- `inazina.performance` INFO 로그에 100ms 이상인 `wallet.snapshot`, `wallet.format`,
  `market.listings`, `chart.query`, `chart.draw` 단계만 기록한다. 사용자 ID·잔액·인자는 기록하지 않는다.
  이 로그는 서버 내부 준비 시간이며 Discord API 왕복 시간은 포함하지 않는다.

임시 DB에서 각 7회 중앙값을 비교했다. 종목 100개(각 2주 보유), 추가 통화 50개이며,
지갑은 정산을 제외한 평가만 측정했다. 차트는 초당 기록 86,400개를 10분봉으로 집계했다.
실제 사용자 DB에 테스트 데이터를 넣거나 봇을 재시작하지 않았다.

| 대상 | 변경 전 | 변경 후 |
|---|---:|---:|
| 전체 종목 조회 | 5.140ms | 1.715ms |
| 지갑 평가 | 2.865ms | 2.522ms |
| 환율 목록 | 2.058ms | 1.460ms |
| 차트 가격 조회·캔들 집계 | 68.724ms | 31.487ms |

마지막 행은 원시 기록 조회+Python 집계와 SQL 집계를 비교한 값이며 PNG 생성 시간은 제외한다.
모든 수치는 로컬 실험으로 실제 Discord 명령어 응답 개선율을 뜻하지 않는다.
DB 스키마·운영 데이터·CPython 기본 실행은 유지한다. 요청 간 가격 캐시나 JIT는 추가하지 않았다.

관련 검사에서는 읽기 중 쓰기 잠금 비점유, 새 요청의 가격 갱신, 종목 조회 결과 일치,
통화 환산 정밀도, 일반/지수 OHLC·PNG 일치, 화면 중간 경계의 변동 기준가와 기록 수,
현재가의 기존/신규 봉 반영, 고가 변경 시 캐시 무효화, 지갑 메인 분리를 확인한다.
기존 기준 통화 환율 검사에서 USD 국적 사용자를 쓰던 데이터는 기준 통화 국적 사용자로 바로잡았다.

### 2026-10-06 적용 기록

지갑은 이자·외환 이자·만기 정산을 먼저 완료한 뒤, 별도의 읽기 전용 연결에서
하나의 WAL 스냅샷으로 평가한다. 화폐 표시·국채 보유·ELS 상세도 조회 시
쓰기 잠금을 예약하지 않는다. 기존 일반 DB 연결과 SELECT 잠금,
거래·송금·정산의 파일 잠금/BEGIN IMMEDIATE/트랜잭션 내부 권한 검사는 유지한다.

보유 종목·옵션 기초자산은 일괄 읽고, 통장·선물 상품은 JOIN한다.
코드 중복 시 기존처럼 평가 제외/확인 필요로 표시한다. 읽기용 데이터는 조회 한 번 동안만
재사용하고 다음 조회에서는 DB Browser 편집을 다시 읽는다. 구형 SQL 스키마명 변환만
최대 512개 문자열을 재사용한다. 대체 후 호출자가 없는 기존 종목 조회 함수는 제거했다.

금액 변환이 필요 없는 지갑·검색·그래프 등은 공통 준비 과정에서 MoneyDisplay를 만들지
않고, 필요한 MoneyDisplay와 검색 임베드 생성은 작업 스레드에서 수행한다.
검색은 개인 이자를 정산하지 않고 메인은 카테고리별 개수만 구한다.
이자는 사용자/상품 대상이 있을 때 직접 WHERE 조건을 구성하고 상품 정보를 일괄 읽는다.

차트는 선택 지표의 공통 계산만 수행한다. SMA는 이동 합계를 사용하고 표준편차·CCI 편차는
창의 평균을 한 번만 구한다. 사각형은 행 단위로 채운다. 최대 16개 PNG를 가격 기록·거래·
봉 주기·표시 종료 시각·지표·VWAP 앵커·ELS 기준선이 모두 같은 경우 재사용한다.
종료 시각이 지정되지 않은 호출은 캐시하지 않는다. 캐시는 금액/거래 권한 판단에 쓰지 않는다.

### 측정

임시 DB의 종목 50개, 종목별 10주 지갑 조회 30회 중앙값이다. Discord API 왕복은 제외했다.
기존 지갑 평가 및 목록과 결과가 같았다. 360개 봉의 37개 지표는 기존 계산과 오차 범위 내
같았고 대표 차트 PNG 바이트도 같았다. 전체 봇이나 실제 Discord 응답시간의 측정은 아니다.

| 대상 | 이전 | 이후 |
|---|---:|---:|
| 지갑 조회 | 8.137ms | 2.238ms |
| 지갑 SELECT | 536회 | 36회 |
| 기본 SMA·거래량 지표 계산 | 3.722ms | 0.156ms |
| 볼린저·슈퍼트렌드·RSI·CCI·MACD 계산 | 4.701ms | 2.031ms |
| 동일 차트 PNG 재사용 | 첫 생성 21.181ms | 재사용 0.014ms |

원본 적용 후 관련 검사 41개를 통과했다. 동시 지갑 읽기에서 미커밋 잔액 비노출,
읽기 연결 쓰기 거부, 동시 송금 초과 지출 방지, 롤백·권한 취소,
화폐 평가·연장이율·검색·ELS 표시·지표·정산을 검증했다.
화폐 일반화 이전 기준 통화 고정 및 모든 외환통장을 외환 카테고리로 가정한 기존 검사 2개는
원본 변경 전에도 실패함을 확인했으며 이번 변경에서 해당 검사 기대값은 수정하지 않았다.

### 적용 범위

자동 승인 검토에서 일반 SELECT 연결 교체를 포함한 광범위한 패치가 거절되어,
기존 연결과 잠금을 유지하는 지갑 전용 읽기 경로로 범위를 줄여 적용했다.
시장 시뮬레이션·시장 전체 종목 조회 구현·봇 사용자 준비 로직·기존 테스트는 유지했다.

### 운영 DB 빈 공간 정리

봇 프로세스가 실행 중이지 않음을 확인한 후 SQLite 백업과 VACUUM을 수행했다.
운영 inazina.db는 590.8MiB에서 28.9MiB로 줄었다. 모든 일반 테이블의 행 수와 전체 값
해시가 전후 같았고 integrity_check도 통과했다. 이 수치는 파일 용량 감소이며 명령어 속도
증가율을 의미하지 않는다. 백업: `/private/tmp/inazina-opt/inazina_before_vacuum.db`.

## 자동 가격 갱신 일괄 처리

가격 갱신은 `inazina.db`의 한 쓰기 트랜잭션에서 독립 상품, 거래소 지수,
ETF와 연결상품, 사건 가격, 옵션·국채 기록을 갱신한다. 후반 작업이 실패하면
앞서 계산한 가격과 지수도 함께 롤백한다. 일별 차트 정리는 커밋 후 별도로 실행한다.

시뮬레이션 상태·자동 목표가·사건은 갱신 시작 시 일괄 조회한다.
변경된 가격·시뮬레이션 상태·자동 목표가·연결상품 가격은 테이블별로 모아
`executemany()`로 저장한다. 옵션 시세는 기초자산·최근 거래·금리를 일괄 조회해
계산하고, 펀드 구성 종목과 ETF 상태도 상품별 재조회를 하지 않는다.

캐시는 한 번의 갱신 동안만 유효하다. 설정과 관리자가 직접 편집한 가격은 다음
갱신에서 다시 읽는다. 쓰기 잠금 획득 대기 한도는 50ms이며, 잠금을 얻지 못하면
그 갱신을 건너뛴다. 이는 갱신 실행 시간의 상한이 아니다.

2026-10-05 운영 DB의 복사본으로 변경 전후를 비교했다. 동일한 복사본과 난수 시드에서
32회 실행하고 초기 2회를 제외한 30회 결과다. SQL 추적을 켠 로컬 측정이며
실제 Discord 왕복 시간은 포함하지 않는다.

| 측정 | 변경 전 | 변경 후 |
|---|---:|---:|
| 갱신 시간 중앙값 | 69.88ms | 43.05ms |
| 갱신 시간 95백분위 | 85.46ms | 56.50ms |
| 마지막 갱신 SELECT 수 | 2,083 | 44 |
| 마지막 갱신 커밋 수 | 11 | 1 |

`executemany()`는 행마다 SQL을 실행한다. 따라서 일괄 저장을 SQL 실행 1회로 세지 않는다.
만기 선물의 과거 가격 확정, ETF 재조정 경계, 구형 사건 변환에는 필요한 개별 조회가
남아 있으며 실제 쿼리 수는 해당 상황과 거래소 수에 따라 달라진다.

GARCH·자동 목표가·사건·휴장 관련 기존 검사 111개와 가격·ETF·지수·후반 실패
롤백 관련 검사 5개를 통과했다. 운영 DB에 가격 갱신을 직접 실행하지 않고
임시 DB에서 검증했다.

## Cython 가격 계산 시범 적용

GARCH 분산·가격과 자동 목표가의 수치 계산만 Cython으로 컴파일한다.
Python 검증, 난수 생성 순서, 금액 반올림, 시각과 DB 처리는 기존 경로를 사용한다.
두 실행 방식은 `managers/_price_math.py` 하나를 공유한다.

### 빌드와 선택

프로젝트 루트에서 다음을 실행한다. 컴파일러가 필요하며 Cython과 setuptools는
빌드할 때만 필요하다. OS·Python 실행 환경이 바뀌면 다시 빌드한다.

```sh
.venv/bin/python -m pip install -r requirements-native.txt
.venv/bin/python build_price_native.py build_ext --inplace
```

`INAZINA_PRICE_BACKEND` 환경변수로 선택한다.

| 값 | 동작 |
|---|---|
| `auto` | 현재 소스와 일치하는 컴파일 파일이 있으면 Cython, 없으면 Python |
| `python` (기본) | 컴파일 파일이 있어도 Python 사용 |
| `cython` | Cython 필수. 파일이 없거나 오래됐으면 시작 시 빌드 안내 오류 |

소스 SHA-256을 빌드에 포함하고 시작 시 비교하므로 오래된 파일은 자동 사용하지 않는다.
변경한 소스를 적용하려면 빌드 후 봇을 재시작한다. 생성된 바이너리와 빌드 디렉터리는
Git 추적 대상에서 제외한다.

현재 선택 확인:

```sh
.venv/bin/python -c "from managers.price_backend import BACKEND; print(BACKEND)"
```

### 검증과 측정

```sh
.venv/bin/python -m unittest tests.test_price_native
.venv/bin/python tools/benchmark_price_native.py --database database/inazina.db
```

벤치마크는 운영 DB를 읽기 전용으로 백업한 뒤 임시 복사본 두 개에서 실행한다.
같은 난수와 시각으로 32회 갱신하고 초기 2회를 제외한 결과를 비교한다.
시뮬레이션 시각이 진행되지 않으면 유효한 속도 비교로 인정하지 않는다.
가격·변동성·목표가·공통 요인·사건·시세 기록·지수·ETF 상태도 비교한다.
실행 중인 봇의 Discord 응답 시간을 측정하는 것은 아니다.

시범 적용 중 GARCH·자동 목표가·호환성 검사 46개가 통과했다.
마무리 시 로더·수치 동등성 4개와 Python 모드의 수학 모델 검사 11개도 통과했다.
최대 가격, 오버플로, 변동성 0, 난수 상태, 반올림 및 컴파일 파일이 없는 환경을 포함한다.

2026-10-08 로컬 CPython 3.14.7 / macOS ARM64에서 측정했다.

| 항목 | Python | Cython |
|---|---:|---:|
| 가격·목표가 계산 10,000회 중앙값 | 42.30ms | 40.24ms |
| 전체 갱신 중앙값 | 18.71ms | 22.74ms |
| 전체 갱신 95백분위 | 39.25ms | 43.34ms |
| 갱신된 시뮬레이션 상태 수 | 130 | 130 |

각 가격 계산 묶음은 7회 측정 중 첫 회를 제외했다. DB 결과 비교는 모두 일치했다.
수치 계산은 약 5% 개선됐지만 전체 갱신의 개선은 확인되지 않아 기본값은 Python이다.
전체 시간에는 DB·파일 I/O와 시스템 부하가 포함되어 이 수치로 모든 환경의 성능을
일반화하지 않는다. 추가 시험 시 `INAZINA_PRICE_BACKEND=cython`으로 켤 수 있다.

# 옵션·금리·사건·투자상품 사용 안내

> Inazina 전환 후의 최신 관리자 명령어·단일 DB·외환·그래프·사건 규칙은 [현재 운영 안내](inazina_operations.md)를 따른다. 아래는 이전 구현의 상세 설명을 포함한다. 관리자 `/사건`·`/상품등록`·`/setup`·`/register`·`/기본소득`은 `$` 설정 창으로 변경됐으며 운영 DB는 `database/inazina.db` 하나다. `/그래프` 인자는 `종목`, 기간은 1일·1시간·30분·10분·5분·1분이다. 모든 카테고리의 기본 상품은 25개씩이다.

## 옵션 명령어와 권한

`/옵션작성`은 **등록된 일반 사용자도 사용할 수 있는 명령어**다. 관리자용 상품 상장과 달리, 사용자가 자기 담보를 제공하고 옵션을 발행하는 기능이다. 콜에는 계약당 주식 1주, 풋에는 계약당 행사가만큼의 현금이 필요하다. 1계약 = 기초주식 1주다.

| 명령어 | 용도 |
|---|---|
| `/옵션체인 [기초주식]` | 거래 중인 콜·풋, 행사가, 만기, IV, 참고 프리미엄, 최우선 매수·매도 호가 조회 |
| `/옵션작성` | 기초주식·콜/풋·행사가·만기·계약수·지정 프리미엄을 정하고 담보를 잠근 뒤 발행 매도 주문 생성 |
| `/내지갑` | 옵션 보유·작성 계약·미판매 수량·담보를 다른 자산과 함께 조회 |
| `/매수 자산:옵션코드 수량:계약수 지정가:프리미엄` | 옵션 매수. 지정 프리미엄 × 계약수를 예치하고 주문을 맞춤 |
| `/매도 자산:옵션코드 수량:계약수 지정가:프리미엄` | 보유 옵션을 다른 사용자에게 재판매 |
| `/호가 자산:옵션코드` | 거래소 주문 목록 조회 |
| `/내주문` | 주문 상태 확인, 선택한 미체결 주문 취소. 작성 주문을 취소하면 미판매분 담보 반환 |

옵션은 기초주식과 같은 거래소에 표시되고 같은 매수·매도 명령어로 거래된다. 실제 체결 프리미엄은 주문 호가가 결정한다. 블랙–숄즈 값은 기준금리를 반영한 참고값이다. 작성자는 자기 옵션을 매수할 수 없다. 현재 구현은 **만기에만 행사하는 유럽형, 주식을 주고받는 실물 결제형**이다.

## 옵션 처리 순서도

```mermaid
flowchart TD
    A[일반 사용자 /옵션작성] --> B{주식·만기·입력·담보 확인}
    B -->|실패| X[오류 안내 · 생성 취소]
    B -->|콜| C[계약수만큼 기초주식 담보 잠금]
    B -->|풋| D[행사가 × 계약수 현금 담보 잠금]
    C --> E[옵션 코드 생성 · 거래소 발행 매도 호가]
    D --> E
    E --> F[다른 사용자 /매수 · 프리미엄 예치]
    F --> G{호가가 맞는가?}
    G -->|아니오| H[미체결 주문 대기 · /내주문에서 취소 가능]
    G -->|예| I[체결 · 프리미엄 지급 · 매수자 옵션 보유]
    I --> J{만기 전인가?}
    J -->|예| K[/매도로 재판매 가능]
    K --> I
    J -->|아니오| L[5초 간격 작업에서 만기 확인]
    L --> M{이익이 있고 행사 준비가 가능한가?}
    M -->|콜 · 행사대금 있음| N[매수자 대금 → 작성자 · 담보 주식 → 매수자]
    M -->|풋 · 기초주식 있음| O[매수자 주식 → 작성자 · 담보 현금 → 매수자]
    M -->|아니오 또는 행사 불가능한 잔량| P[행사하지 않은 계약 만료]
    N --> Q[남은 담보 반환 · 주문 만료 · 계약 정산 기록]
    O --> Q
    P --> Q
```

행사 준비가 일부만 가능하면 가능한 수량만 행사한다. 콜 매수자는 만기에 행사가를 낼 자금이, 풋 매수자는 팔 기초주식이 필요하다. 프리미엄을 지급했다고 콜 행사대금까지 미리 낸 것은 아니다. 작성자가 이미 판매한 계약은 재판매 여부와 관계없이 만기까지 의무가 남는다.

## 옵션 조회 오류 수정

옵션 정보는 `/내지갑`과 `/옵션체인`에서 조회한다. 기초주식 조회의 전체 코드 중복 검사는 통합 DB 안에서 실행된다. 실제 옵션 발행·매수 후 체인, 보유자, 작성자 조회를 회귀 테스트로 검증했다.

## 기준금리와 법정최고이자

일반 사용자는 `/검색` → **기준·시장금리 · 법정최고이자**에서 국가별 기준금리를 확인하고, `/법정최고이자 국가:<국가 ID>`로 이율 상한을 조회한다. 값은 `country_currencies.base_rate`와 `country_currencies.legal_max_rate`에서 국적별로 관리한다.

| 항목 | 국가 컬럼 | 적용 |
|---|---|---|
| 기준금리 | `base_rate` | 관리자가 결정하는 정책금리. 시장 수익률곡선으로 전달되지만 시장지표 연동 계약에 직접 대입하지 않음 |
| 법정최고이자 | `legal_max_rate` | 해당 국적의 대출 상품·계약·연체이율 상한. 예금과 채권 쿠폰에는 적용하지 않음 |

DB Browser에서는 `country_currencies`를 수정하거나 `$금리수정`, `$법정최고이자수정`을 사용한다. 기준금리는 -100~100%, 법정최고이자는 0~100%다. `$시장금리수정 [국적] [funding/bank_bond/treasury] [만기일수] [금리%]`로 수익률곡선의 한 구간을 수정한다. 기준금리 변경 시 구간별 `pass_through`만큼 조달금리·은행채금리·국채금리가 이동하며, 기준금리 결정 자체는 자동화하지 않는다. 같은 통화를 여러 국적이 공유하고 대출 국적이 없으면 가장 낮은 상한을 사용한다. 상한을 낮추면 기존 대출 상품과 계약금리도 즉시 낮아진다.

`market_rate_curve`는 국가·지표·만기별 시장금리와 정책금리 전달계수를, `market_rate_curve_history`는 관측일별 이력을 저장한다. 여기에 실제 예금·대출 잔액, 부실대출 비율, 국채 발행 소진율로 계산한 수급 조정을 `market_rate_pressure`와 이력에 저장해 조달·은행채·국채 곡선에 더한다. `financial_institutions`에서는 발행기관별 조달 스프레드, 운영비, 유동성 비용, 목표마진, 경쟁 조정뿐 아니라 `equity_capital`, `retained_earnings`, 목표 자기자본·예대율, 자금·자본·경쟁 민감도, 지급준비율과 예금보호 한도를 관리한다. 예금이자 비용, 대출이자·취급수수료 수익, 부도 손실과 회수액은 `financial_institution_ledger`에 한 번만 기록되어 유효 자기자본에 반영된다. 이 값은 SQL Browser에서 변경할 수 있고 다음 광고금리 재산정과 신규 계약에 반영된다.

금리 값을 저장한 뒤에는 봇을 재시작할 필요가 없다. 새 국가 인자를 Discord에 반영하려면 수정된 코드로 봇을 한 번 재시작하여 명령어를 동기화해야 한다.

금리 그래프는 `/그래프`에서 **기준금리** 또는 **법정최고이자**를 입력해 연다. 세로축은 연이율(%)이며 금리에는 거래량·가격 기술지표를 표시하지 않는다. `/검색`의 금리 카테고리는 국적별 기준금리와 법정최고이자를 함께 표시한다.

### 상품금리와 계약금리

저축·대출 상품은 `rate_type`으로 `fixed`(고정) 또는 `floating`(변동)을 선택한다.

- 고정금리 상품은 관리자가 정한 `interest_rate`를 광고한다. 가입 시 계약에 금리를 복사하므로, 이후 상품 이율을 고쳐도 이미 체결된 예금·대출에는 소급되지 않는다.
- 변동금리는 `benchmark_key`(`policy`, `funding`, `bank_bond`, `treasury`)와 `benchmark_tenor_days`로 지표·만기를 지정한다. 만기 사이에서는 금리 자체가 아니라 로그 할인계수를 보간해 일관된 할인계수를 만든다.
- 예금금리는 지표에 상품 만기·프로모션·경쟁 조정을 더한다. 대출금리는 여기에 금융기관 조달·운영·유동성 비용과 목표마진을 더한다. 기관의 실제 예금·대출 잔액, 자기자본비율, 목표 예대율, 시장점유율도 신규 계약과 광고금리 재산정의 동적 가산·할인에 반영된다.
- 대출 계약은 신용점수뿐 아니라 유효 연소득(`annual_income × income_stability`), DTI, DSR, 기존 연체·부도 이력을 함께 심사한다. `max_dti_percent`와 `max_dsr_percent`가 0이면 기존 상품 호환을 위해 해당 제한을 사용하지 않고, 양수이면 소득 등록과 한도 통과가 필수다. 신용점수 가산금리 외에 `borrower_history_spread_max`, `affordability_spread_max` 범위의 계약별 가산금리를 붙이고 심사 시점의 소득·DTI·DSR·위험점수를 대출 계약에 보존한다. 담보비율에 따라 `collateral_discount_max`만큼 낮춘다. `collateral_required_ratio`는 최소 담보다. 현금 또는 같은 결제통화의 보유 자산을 담보로 쓸 수 있으며 자산은 `collateral_haircut`만큼 차감 평가한다. 시세 변동으로 `margin_call_ltv`를 넘으면 마진콜, `liquidation_ltv`를 넘으면 매수호가를 가격·시간 우선으로 소진한다. 남은 수량만 유동성·발행량에 따른 시장충격과 헤어컷을 적용한 정리 백스톱으로 넘기며 `liquidation_cost_percent`를 차감한다. 체결·백스톱 수량과 총·순회수액은 `collateral_liquidation_events`에 기록한다. 신규 대출은 기관별 예금·유효자기자본에서 지급준비금을 제외한 자금 한도와 위험가중 자기자본 한도를 모두 통과해야 한다. 자본비율이 목표 아래면 `restricted`, 유효자기자본이 0 이하이면 `failed`가 되어 신규 대출이 중단된다.
- 계약은 `repricing_cycle_seconds`마다 `repricing_lag_seconds` 전 관측일의 지표를 읽어 재산정한다. 새 금리를 과거 기간에 소급하지 않으며, 예정 재산정일·관측일·이전/신규 금리·상환표 재산정 건수를 `contract_rate_reset_history`에 계약별로 보존한다.
- 법정최고이자는 대출 광고금리·계약금리·연체금리에 적용하고, 신규 대출은 취급수수료와 `mandatory_cost_percent`로 설정한 의무 보험·중개 등 법정 산입비용을 모두 실수령액 기준 연율로 환산해 국적별 상한을 검사한다. 두 비용은 APR 현금흐름에도 포함된다. 예금금리와 국채·회사채 쿠폰은 제한하지 않는다.

채권 쿠폰은 발행 시 고정된다. `coupon_frequency_days=0`은 기존 만기 일괄 이자, 양수는 정기 쿠폰이다. 각 현금흐름을 국채 제로금리곡선의 해당 만기 할인계수로 평가하며 회사채에는 `credit_spread`와 `liquidity_spread`를 더한다. 보유 국채에는 발생이자와 클린·더티 가격을 구분하고 시장 갱신 시 국채 시가도 곡선으로 재평가한다. 대출 만기 뒤에는 `delinquency_spread`를 더한 연체이자를 법정최고이자 안에서 계산하며, 유예·기한이익 상실·채무불이행 단계와 담보 처분을 순서대로 적용한다. 상품별 `day_count_convention`은 `ACT/365`, `ACT/360`, `30/360`을 지원한다.

`country_rate_history`는 국가별 기준금리·법정최고이자의 적용 시각을 저장한다. 봇 명령뿐 아니라 DB Browser에서 직접 수정한 값도 기록하므로, 봇이 잠시 중단되었어도 변동계약의 다음 재산정 값을 다시 계산할 수 있다.

표시에서는 명목 연이율과 복리 주기를 반영한 실효 연이율을 구분한다. 대출 APR은 선취 수수료와 실제 약정 현금흐름의 내부수익률로 계산한다. `amortization_type`은 기존 방식 `legacy`, 만기일시 `bullet`, 원금균등 `equal_principal`, 원리금균등 `annuity`를 지원하며 새 방식은 `loan_payment_schedule`에 회차별 원금·이자·납부 상태를 저장한다. 상환표 이자는 상품의 일수계산 방식과 조정된 납부일을 사용하고, 변동금리가 재산정되면 이미 납부한 회차는 보존한 채 미래 미납 회차의 원금·이자와 APR을 다시 계산한다. 중앙은행의 기준금리 결정만 관리자 권한으로 남아 있고, 결정된 금리의 시장 전달과 계약 재산정은 자동 처리된다.

만기 전 예금 해지는 계약에 스냅샷된 `early_withdrawal_rate`로 허용 이자를 다시 계산하고 초과 지급 이자와 `early_withdrawal_fee_percent`를 차감한다. 일반 예금의 `deposit_insured`가 켜져 있고 기관이 `failed`가 되면 예금자·기관별 `deposit_insurance_limit` 한도까지 국고가 현금으로 지급한다. 초과액은 `uninsured_claim`과 `deposit_insurance_claims`에 채권으로 보존되고 해당 기관의 신규 예금·대출 상품은 중단된다. 외환통장은 부실기관에서 추가 이자와 신규 개설을 정지하며 별도 외화 정리 절차 대상으로 남긴다. 대출 상환표의 납부일은 주말과 `financial_holidays`를 피해 `business_day_convention` 규칙으로 조정한다.

수동 조기상환에는 계약 시점에 스냅샷된 `prepayment_fee_percent`를 적용한다. `prepayment_fee_decline_days`가 0이면 만기 전 고정 비율, 양수이면 실행일부터 해당 기간 동안 선형으로 0까지 체감한다. 수수료는 대출 잔액을 줄이지 않고 금융기관 손익원장에 별도 기록한다.

## 관리자 호재·악재 사건

관리자가 **`/사건`만 실행하면** 입력 창이 즉시 열린다. 명령어에는 입력 매개변수가 없으며 아래 다섯 항목을 창 안에서 설정한다. 창을 연 관리자만 제출할 수 있고, 제출 직전에도 관리자 권한을 다시 확인한다.

| 창 항목 | 입력 |
|---|---|
| 자산 선택 | 현재 사건을 적용할 수 있는 자산, 또는 시장 전체. 고정·만료·연동 상품은 제외 |
| duration | 1~604,800초 사이 정수 |
| 호재 / 악재 | 선택 상자에서 선택 |
| 변동성 | `%` 없이 0~100 사이 숫자. `30.5`처럼 소수도 가능 |
| 목표 가격 (선택) | 비워 두거나 1~9,007,199,254,740,991 사이 정수 NWX |

Discord 선택 상자의 최대 항목 수는 25개다. 적용 가능한 개별 자산이 25개 이상이면 자산 선택 항목이 코드·이름 입력칸으로 바뀐다. 정확한 코드나 이름을 입력하고, 전체 적용은 `시장 전체`로 입력한다.

목표 가격을 비워 두면 호재 `N`의 최종 목표는 등록 당시 가격의 +N%, 악재 `N`은 -N%다. 악재 100%의 최저 거래 가격은 1 NWX다. 시장 전체를 고르면 적용 가능한 각 종목의 시작 가격을 기준으로 계산한다. 변동률 0에 목표 가격도 없으면 사건 가격 효과 없이 기존 가격 변동을 계속한다.

목표 가격을 입력하면 그 가격이 최종 목표가 되고, **변동률은 이동 중 무작위 변동의 크기**를 조절한다. 목표 가격은 개별 자산을 선택했을 때만 사용할 수 있다. 호재 목표는 현재 가격 이상, 악재 목표는 현재 가격 이하여야 한다. 예를 들어 100 NWX 자산에 악재·30%·60초·목표 가격 40을 입력하면 중간에는 30% 설정에 따른 무작위 흔들림을 주고 60초 시점에 40 NWX로 도달한다. 목표 가격을 입력한 경우의 변동률 0은 무작위 흔들림 없는 경로다.

사건 동안에는 목표를 향한 경로에 **틱마다 무작위 상승·하락**을 섞는다. 악재라도 중간에 반등할 수 있고, 호재라도 중간에 하락할 수 있다. 입력 비율이 클수록 흔들림이 커지며, 종료 시각에는 목표 가격에 정확히 맞춘다. NWX 정수 반올림으로 작은 움직임은 일부 틱에서 같은 가격으로 보일 수 있다. 종료 뒤에는 기존 가격 변동을 사용한다. 봇이 종료 시각에 멈춰 있었다면 다음 가격 갱신에서 먼저 목표를 적용한다.

사건과 종목별 시작·목표 가격, 무작위 경로 상태는 `system.db`의 `market_events`, `market_event_targets`에 저장하여 재시작해도 이어진다. 같은 시각의 가격 갱신을 반복해도 무작위 변동을 다시 누적하지 않는다. 같은 종목에 새 사건을 등록하면 현재 가격에서 새 목표로 시작하고 그 종목의 이전 사건 경로를 대체한다. 고정·만료·연동 자산은 자산 선택 목록에서 제외한다. 선물·채권·펀드 같은 연동 상품에는 기초 주식의 사건 효과가 평가식에 따라 반영된다.

## 추가 상품과 명령어

`/상품등록`은 **관리자 전용 명령어**다. 일반 사용자는 상품을 등록할 수 없고, 등록된 상품의 거래·가입·환매를 이용한다. 관리자는 종류, 코드, 이름, 가격, 발행량, 거래소, 기초, 만기일수, 연이율, 계약승수를 입력하여 등록한다. 실제 종목명·발행 회사를 임의로 만들지는 않았다.

| 종류 | 기초 입력 | 거래 방법 | 동작 |
|---|---|---|---|
| 주식 선물 | 주식 코드 | `/매수`·`/매도`, `/선물증거금` | 롱/숏, 초기 증거금 20%, 유지증거금 15%, 5초 간격 손익 정산, 증거금 미달 청산, 만기 현금 정산 |
| 회사채 | 발행 회사 코드 | `/매수`·`/매도` | 매수 발행대금이 회사 자본으로 입금, 설정 시 정기 쿠폰 지급 또는 만기 일괄 이자, 만기 원금 상환, 이자 과세, 회사 자금 부족 시 채무불이행 상태로 청구권 유지 |
| 일반 펀드 | 구성 주식 거래소 ID | `/매수`·`/매도`(지정가 생략) | 최초 시가총액 비중으로 주식 바스켓 생성, 구성 종목 가격을 반영한 NAV |
| 인덱스 펀드 | 지수 거래소 ID | `/매수`·`/매도`(지정가 생략) | 해당 거래소 시가총액 가중 지수를 1배 추종 |
| 현물 원자재 | 불필요 | `/매수`·`/매도` | 유한 공급의 현물 소유 수량과 거래소 호가 거래 |

회사채의 `가격`은 액면가, 펀드의 `가격`은 최초 NAV, 현물의 `가격`은 1개 단가다. 선물은 기초 주가와 기준금리로 가격을 계산하고 계약승수는 1계약당 주식 수다. 선물·회사채에는 만기가 필요하며 펀드는 만기일수 0으로 등록한다. 원자재의 이름에 금 1g·원유 1배럴처럼 거래 단위를 명시하면 된다.

일반 펀드 구성은 `product.db.fund_components`의 `weight`, `base_price`로 관리할 수 있다. 가중치는 양수로 입력하며 합으로 정규화한다. 현재 NAV는 최초 NAV × 구성 종목별 가격 비율의 가중 평균이다. 신규 구성 종목을 넣을 때 기준가격도 함께 설정한다.

선물의 국고 정산 호가는 다른 사용자 주문을 먼저 확인한 뒤 유동성을 제공한다. 선물 평가액은 명목금액이 아니라 담보 증거금+미정산 손익이다. 게임용 손실 한도는 해당 포지션 증거금이며 초과 결손은 국고 정산자가 부담한다. 실제 선물 시장의 추가 손실 청구를 그대로 복제한 모델은 아니다. 펀드의 가입·환매도 가상 운용자 역할을 하는 국고와 결제한다. 회사채는 국고가 대신 원리금을 지급하지 않으며 발행 회사에 자금이 추가되면 만기 상환을 재시도한다.

## 자동 가격 변동 알고리즘

자동 가격 갱신에는 **로그수익률 + GARCH(1,1) + 시장 공통 요인 + 종목 고유 충격 + 사건 점프**를 사용하며, 일반 자동 변동에 **주기적인 근처 목표가격과 목표 방향 회귀**를 추가했다. GARCH의 분산식, 시장 공통 충격, 종목별 충격, 관리자 사건의 처리 순서는 유지한다. 자유롭게 가격이 움직이는 주식과 현물 자산에 적용한다. 선물·회사채·펀드·지수 연동 상품은 기존 기초 자산·금리·NAV 평가식을 사용하므로 기초 주가의 변동이 평가 가격으로 이어진다. 고정 자산과 만료 상품에는 무작위 가격 변동을 적용하지 않는다.

GARCH는 큰 변동 뒤에도 높은 변동성이 이어졌다가 서서히 평소 수준으로 돌아오는 현상을 모델링한다. 가격은 `P_next = P × exp(log_return)`, 조건부 분산은 `h_next = ω + α × ε_previous² + β × h_previous`로 계산한다. `ε`는 직전 수익률에서 드리프트를 뺀 충격이다. 시장 충격과 종목 충격은 각각 분산을 1로 조정한 Student-t(자유도 6)를 사용하여 정규분포보다 큰 급등락이 더 자주 나오도록 했다. 같은 가격 갱신 시각에는 시장 공통 충격을 공유하고, 각 종목에 독립 충격을 섞는다. 상승장·하락장은 ±10% 연율의 작은 드리프트로 반영한다. 참고: [Bollerslev의 GARCH 원문 (1986)](https://public.econ.duke.edu/~boller/Published_Papers/joe_86.pdf).

일반 가격의 로그수익률은 `drift + 목표방향보정 − h/2 + √h × (ρ × 시장충격 + √(1−ρ²) × 종목충격)`이다. 자동 목표 방향 보정은 `0.08 × log(목표가격 / 내부 현재가격)`이다. 목표 방향으로 끌어당기는 드리프트는 GARCH의 직전 충격에서 제외하여 목표와의 거리만으로 변동성이 폭주하지 않게 한다. 자동 목표가격, 사건 점프와 목표가격에 맞추는 경로는 게임 규칙에 맞춘 확장이며 원문의 실증 결과를 그대로 재현한 모형은 아니다.

초기 설정은 `α=0.05`, `β=0.90`, 연 변동성 30%, 시장 공통 충격 계수 0.55, 자유도 6이다. `ω=(1−α−β)×목표 틱 분산`으로 설정한다. **실제 1초의 갱신을 게임 내 거래 1분**으로 환산하며 1년은 252거래일×390분이다. 따라서 연 변동성 30%를 매초 가격에 직접 적용하지 않는다. 수치는 이 게임을 위한 초기 설정이며 실증 자료로 추정한 값은 아니다.

DB Browser에서 `system.db`의 `settings.value`로 다음 설정을 조정할 수 있다. 저장한 값은 다음 가격 갱신부터 읽으며 기존 값을 봇 재시작으로 덮어쓰지 않는다.

| `settings.key` | 초기 값 | 의미·범위 |
|---|---:|---|
| `garch_alpha` | `0.05` | 직전 충격의 제곱이 다음 분산에 미치는 계수. 0 이상 |
| `garch_beta` | `0.90` | 직전 분산을 유지하는 계수. 0 이상, `alpha + beta < 1` |
| `garch_annual_volatility` | `0.30` | 목표 연 변동성의 소수 비율. 0보다 큼, `0.30 = 30%` |
| `garch_market_correlation` | `0.55` | 시장 공통 충격 계수. 0~1, 동일 계수를 쓰는 종목쌍의 충격 상관은 계수의 제곱 |
| `garch_step_seconds` | `1` | 가격 모형의 갱신 간격. 1~86,400 정수 초 |
| `garch_trading_minutes_per_step` | `1` | 갱신 한 번에 해당하는 게임 내 거래 분. 0보다 큼 |
| `garch_student_df` | `6` | Student-t 자유도. 유한한 분산을 위해 2보다 큼 |

설정은 모두 유한한 숫자여야 하며 잘못된 전체 설정은 가격 갱신에서 오류로 알린다. 일반 자동 가격의 한 번 갱신은 최대 -20%/+20%로 제한하고 최소 가격은 1 NWX다. 관리자가 지정한 사건의 최종 가격은 별도로 적용한다.

기존 `system.db.settings.market_volatility`와 종목별 `market_volatility`는 계속 사용할 수 있다. 기본값 `0.15`가 위 연 변동성 30%에 해당하며 값의 비율만큼 목표 변동 강도를 조절한다. `0`이면 일반 자동 변동과 분산 갱신을 멈추고 최근 변동성 기억을 유지한다. 종목별 값이 있으면 전체 설정을 대신 사용한다. 사건은 관리자에게 지정받은 목표까지 이동하는 별도 효과이므로 자동 변동을 멈춘 상태에서도 실행된다.

### 반복 자동 목표가격

`/사건` 없이도 현재 가격의 **±10% 안에서 목표가격**을 정하고, **60~180초 동안** 그 방향으로 회귀하면서 큰 무작위 등락을 준다. 기간이 끝나면 그때의 현재 가격을 기준으로 새 목표를 정하고 같은 과정을 반복한다. 예를 들어 현재 가격이 100 NWX이면 처음 목표는 90~110 NWX 안에서 뽑고, 다음 주기에는 그때의 가격을 기준으로 다시 뽑는다. 목표는 오를 수도 내릴 수도 있고, 가격은 목표를 넘거나 반대 방향으로 움직일 수도 있다. 자동 목표는 확정된 만기 가격이 아니므로 주기 끝에 목표로 가격을 강제 이동시키지 않는다.

기본 무작위 변동 강도는 기존 GARCH의 목표 표준편차 **6배**다. GARCH의 장기 목표 변동성에 이 배율을 곱하고 기존 분산식을 그대로 적용한다. 무작위 수익률에만 매번 6을 곱하는 방식으로 충격을 되먹이지 않는다. 기존 `market_volatility=0.30`, 연 변동성 설정 `0.30`, 1초=게임 거래 1분이면 처음의 한 번 갱신 표준편차는 약 **1.15%**이며 실제 크기는 GARCH의 최근 충격과 무작위 표본에 따라 달라진다. 종목별 `market_volatility=0`이면 자동 목표의 회귀 효과도 멈춘다.

한 주기의 과도한 이탈을 막기 위해 시작가격과 목표가격 중 작은 값의 75%부터 큰 값의 125%까지를 가격 범위로 사용한다. 한 번의 -20%/+20% 제한과 최소 1 NWX도 유지한다. 새 주기의 기준은 다음 목표를 고르는 시점의 현재 가격이므로 가격이 장기적으로 계속 같은 범위에 갇히는 것은 아니다.

`system.db.settings`에서 다음 값을 조정한다. `auto_target_enabled=0`으로 저장하면 반복 자동 목표를 끄고 기존 GARCH 자동 변동을 사용한다. 현재의 `garch_*` 및 `market_volatility` 설정값은 이 기능을 켜기 위해 덮어쓰지 않는다.

| `settings.key` | 초기 값 | 의미·범위 |
|---|---:|---|
| `auto_target_enabled` | `1` | 반복 자동 목표 사용 여부. `0` 또는 `1` |
| `auto_target_range_percent` | `10` | 새 목표를 정하는 현재가 대비 ±범위(%). 0~50 |
| `auto_target_min_seconds` | `60` | 목표 주기의 최소 실제 초. 1~604800 정수 |
| `auto_target_max_seconds` | `180` | 목표 주기의 최대 실제 초. 최소 이상, 1~604800 정수 |
| `auto_target_pull` | `0.08` | 로그 가격 차이를 따라가는 회귀 계수. 0~1 |
| `auto_target_noise_multiplier` | `6` | 기존 GARCH 목표 표준편차에 곱하는 강도. 1~30 |
| `auto_target_band_percent` | `25` | 주기 시작·목표가격 바깥으로 허용하는 범위(%). 0~100 |

설정은 다음 갱신부터 읽으며 이미 정한 목표가격과 종료 시각은 유지한다. 목표의 범위와 최소·최대 기간 변경은 다음 주기에 반영된다. 관리자 `/사건` 진행 시에는 자동 목표를 지우고 사건의 목표·기간·변동성을 우선 적용한다. 사건 종료 후 다음 일반 갱신에서 사건 종료 가격을 기준으로 새 자동 목표를 만든다. SQL로 현재 가격을 직접 바꾸거나 고정하면 이전 자동 목표를 지우고 새 현재 가격을 기준으로 다시 시작한다.

내부 가격은 소수로 유지하고 표시·거래 가격을 정수 NWX로 반올림한다. 저가 종목에서 1 NWX보다 작은 변화도 다음 갱신에 누적된다. 내부 가격과 조건부 분산, 최근 충격은 `system.db.market_simulation_state`, 같은 갱신 시각의 공통 충격은 `system.db.market_factor_state`, 자동 목표와 주기 시각은 `system.db.market_auto_targets`에 저장하므로 봇을 재시작해도 이어진다. 그래프의 날짜별 가격 기록 삭제는 이 상태를 지우지 않는다. SQL Browser로 현재 가격을 직접 바꾸거나 고정 상태를 전환하면 내부 가격의 기준도 현재 가격으로 맞춘다. 시각을 `garch_step_seconds` 단위로 나눈 같은 구간은 한 번만 갱신하므로 중복 호출에서도 충격을 다시 적용하거나 자동 목표를 다시 뽑지 않는다.

봇이 오래 멈췄다가 실행되어도 중단된 시간만큼 무작위 충격을 한꺼번에 생성하지 않는다. 다음 호출에서 최대 한 번의 가격 모형 갱신만 진행한다. 사건의 duration은 실제 경과 시간을 사용하므로 사건 종료 뒤 다시 실행하면 지정된 최종 목표를 적용한다.

`/사건`은 기존의 **기간 끝에 정확한 목표 가격·변동률을 적용하는 규칙**을 유지한다. 사건 동안 GARCH 충격과 시장·종목별 충격을 목표 경로에 섞고, 사건의 가격 충격을 분산에 반영하여 사건이 끝난 직후에도 높아진 변동성이 서서히 진정된다. 무작위 경로는 중간에 오르내리지만 최초 등록 시각에는 가격을 뛰게 하지 않는다. 사건 기간 중 첫 모형 갱신에서 호재·악재 방향의 점프를 한 번 적용하며, 이 점프가 목표 경로에서 차지하는 효과는 남은 시간에 따라 감쇠한다. 적용 시각을 `market_event_targets.jump_applied_epoch`에 기록해 갱신 간격이나 재시작 때문에 점프가 누락·반복되지 않게 한다. 종료 시점에는 지정 목표를 적용하고 이후 일반 자동 가격 변동으로 돌아간다. 일반 변동성을 `0`으로 설정해도 사건에서 정한 %에 따른 무작위 흔들림과 목표 이동은 유지한다.

첫 점프는 입력 %의 10% 크기를 갖는다(예: 50% 입력은 호재 +5%, 악재 −5%의 잔여 경로 충격). 사건의 무작위 경로에서는 표준화 충격을 ±3까지, GARCH에 따른 변동 강도 배율을 최대 3배까지 제한한다. 이 점프와 흔들림은 남은 기간에 따라 감쇠하므로 사건 종료 시 목표가격은 바뀌지 않는다. %가 0이고 목표가격만 지정되면 무작위 사건 충격 없이 목표로 이동한다.

## 적용과 검증

봇을 재시작하면 새 DB 테이블·열이 생성되고 명령어가 서버에 다시 동기화된다. 기존 계좌·보유 수량을 삭제하는 초기화는 하지 않는다. 원래 등록된 일반 `futures` 투자상품은 자동으로 새 주식 선물 계약으로 변환하지 않는다. 새 계약은 `/상품등록`의 주식 선물 종류를 사용한다.

금리 그래프 검증은 `.venv/bin/python -m unittest tests.test_rate_graphs -q`로 실행한다. 조회 시작의 기존 적용 금리, 소수 적용 시각, 같은 시각의 변경 순서, 미래 이력 제외, 0%·100%, 수평·수직 계단 표현, DB Browser 변경과 비소급 이자 유지, 날짜 정리 뒤 이력 보존을 확인한다. 자산 없는 선택 목록, Discord의 25개 선택 제한, 자동완성, 모든 기간의 PNG, 기간 변경·새로고침, 소유자 권한, 금리 직접 조회와 한국어 명령어 등록도 임시 DB에서 검증한다.

검증 명령: `.venv/bin/python -m unittest -q`. 반복 자동 목표의 현재가 기준 범위·기간·회귀·큰 상승과 하락·주기 교체·이탈 범위·재시작·중복 호출·SQL 재기준·사건 우선순위·연동 상품 제외·설정 변경·잠긴 DB의 목표/상태 롤백을 확인한다. GARCH 분산식·충격 뒤 분산의 군집과 회귀·Student-t의 단위 분산과 큰 꼬리·시장 공통/독립 충격·소수 가격 누적·재시작과 중복 갱신·SQL 가격 수정·고정 및 0 변동성·잠긴 DB의 가격/상태 롤백·사건 목표와 상태 보존도 확인한다. 옵션 조회·만기 인도, 금리 변경 시점별 계산과 DB Browser 방식의 직접 DB 편집, 금리 입력 검증·이력 보존, 권한, `/사건` 단독 실행·창 안의 다섯 입력·0~100%·가격/변동률 목표·무작위 상승/하락·재시작·중복/지연 갱신·사건 대체, 그래프 가격 기록의 한국시간 날짜별 정리, 지표 계산·빈 데이터·PNG 생성, 회사채 상환·채무불이행, 펀드 NAV·환매, 선물 롱/숏·증거금·청산·만기·주문 취소도 로컬 임시 DB에서 검증한다. 실제 Discord 서버에서의 명령어 동기화와 창 제출은 봇 재시작 후 확인해야 한다.
